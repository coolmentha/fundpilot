# 养基宝持仓导入

## Goal

让用户通过养基宝二维码登录，读取多个养基宝账户的基金持仓，预览并选择要导入 FundPilot 的记录；导入只复用 FundPilot 现有的新建基金和持仓调整流水能力。

## Background

- 养基宝 `/qr_code` 与 `/qr_code_state/{id}` 是公开接口，但仍需匿名签名：空 `Authorization`、秒级时间戳、`MD5(path + "" + TsSec + secret)`。已实测 HTTP `GET /qr_code` 返回 `200 SUCCESS`、二维码 URL 和登录会话 ID。
- 扫码成功后取得 Token；账户和持仓接口使用通用签名 `MD5(MD5(path) + token + TsSec + secret)`，其中 path 不含 query string。
- `/user_account` 提供账户 ID 和名称；`/fund_hold?account_id={id}` 提供持仓 ID、基金 code/name、`hold_share` 和 `hold_cost`。
- FundPilot 已有“新建基金并录入初始持仓”能力，也已有 `ADJUST_IN/ADJUST_OUT` 调整事实持仓份额流水。
- 当前系统是共享管理 API Key 下的单租户数据；下一版本可能加入多用户，但本期不做用户体系或业务数据隔离。

## Requirements

- R1. 后端创建二维码导入会话并代理扫码状态查询；前端只持有随机 FundPilot 会话 ID，不接触养基宝 Token。
- R2. Token 只保存在后端短期内存会话中，30 分钟过期；完成、取消或超时立即清除。Token、签名和完整敏感响应不得写日志、数据库或前端持久化存储。
- R3. 扫码成功后读取全部养基宝账户及其持仓，预览显示来源账户、基金、份额、成本、FundPilot 当前份额和匹配状态。
- R4. 用户可以逐项选择导入记录。同一基金 code 在多个养基宝账户出现时独立展示、不合并，但最多选择其中一份。
- R5. FundPilot 不存在该 code 时，复用现有新建基金与初始持仓语义，`hold_share` 作为份额，`hold_cost` 作为成本单价。
- R6. FundPilot 已存在该 code 时，用户必须逐项明确选择“以本系统为准”或“同步为养基宝份额”；未选择处理方式时不能提交。
- R6.1. “以本系统为准”不写数据库；“同步为养基宝份额”将 `hold_share` 作为最终目标份额，按它与提交时 FundPilot 当前事实份额的差额生成至多一笔现有 `ADJUST_IN` 或 `ADJUST_OUT` 流水；差额为零不生成流水。
- R6.2. 调整不得改写基金基本信息、成本单价或既有流水；lot 变化完全沿用现有 ADJUST 语义。
- R7. 导入逐项返回成功、跳过或失败结果。单项失败不得产生半成品，也不得阻断其他项；同一会话重复或并发提交不得重复创建基金或调整流水。
- R8. 外部调用设置超时，并将 404、超时、签名失败、Token 失效、二维码过期和字段缺失映射为可诊断且不泄露凭据的错误。

## Acceptance Criteria

- [ ] 可以生成可扫码二维码，并在扫码成功后列出全部账户及其基金持仓。
- [ ] 导入预览支持全选、取消和逐项选择，清楚展示新基金、已有基金及来源账户。
- [ ] 同 code 多账户版本不合并；选择一份后，其他版本不可同时选择，后端提交校验同样生效。
- [ ] 新基金通过现有初始持仓路径创建，导入份额和成本与预览一致，并生成现有语义的已确认 `INCREASE` 交易。
- [ ] 已有基金必须由用户选择保留本系统份额或同步；选择同步时按锁后事实份额差额生成至多一笔 `ADJUST_IN/ADJUST_OUT`，零差额不写流水。
- [ ] 未选项与“以本系统为准”项不产生数据库写入，已有基金的成本单价、基本信息和既有流水不被改写。
- [ ] 单项失败不影响其他项；重复或并发提交不重复写账，每项结果清晰可见。
- [ ] 完成、取消、超时和应用重启后会话不可继续使用，日志与响应不泄露 Token 或签名。
- [ ] 现有基金创建、手动调整、lot、行情刷新及设置页回归测试继续通过。

## Out Of Scope

- 将养基宝接入盘中估值、历史净值、基金字典、指数行情或任何数据源优先级。
- 后台轮询、长期同步或向养基宝反向写入基金、交易和策略。
- 导入养基宝历史收益曲线、历史交易流水或定投计划。
- 多用户认证、用户隔离、Token 长期保存和现有业务数据归属迁移。
- 新增持仓表、额度模型、导入账本或其他独立业务模型。
