# 多用户数据隔离与管理员权限

## Goal

支持多个用户独立使用 FundPilot；管理员也是用户，但具备管理用户、分配角色和执行系统管理操作的权限。

## Confirmed Facts

- 当前仅支持一个 `ADMIN_API_KEY` 及签名 Cookie，会话中没有用户身份。
- 当前基金记录同时承载用户持仓属性与基金产品身份，净值历史、行情快照均关联该记录。
- 基金基础资料、净值历史、市场指标、指数 K 线、交易日历及基金字典必须全局共享。
- 持仓、交易、策略、定投、分组、信号、用户配置及操作确认必须按用户隔离。
- 管理员也是普通用户，可使用个人数据功能；管理员才可看到并访问管理菜单和管理 API。

## Requirements

- 用户拥有至少 `USER` 与 `ADMIN` 两种角色。
- 所有用户私有读取和写入必须从服务端会话取得当前用户，不能信任请求中的用户 ID。
- 管理员可列出用户、启用/停用用户并分配角色。
- 非管理员访问管理接口必须被拒绝；前端不得显示管理入口。
- 现有单用户数据必须可迁移到一个初始管理员。
- 共享基金行情只保存一份，并可被所有用户的同代码基金使用。
- 用户使用用户名和密码登录；密码只保存不可逆安全哈希，管理员可设置初始密码。
- 权限模型仅包含 `USER` 与 `ADMIN` 两种角色；管理员分配权限即切换角色。

## Acceptance Criteria

- [x] 两个普通用户不能通过任意现有业务 API 读取或修改对方的私有数据。
- [x] 同一基金代码的净值与行情数据不因用户数量重复存储。
- [x] 管理员可管理用户角色和启停状态，普通用户无法调用对应 API。
- [x] 管理员菜单仅在管理员会话中显示，直接访问 `/admin` 也受保护。
- [x] 迁移后既有数据仍可作为初始管理员的数据正常读取。

## Confirmed Initialization

- 管理员通过管理页创建用户并设置初始密码。
- 首个管理员由 `FUNDPILOT_BOOTSTRAP_USERNAME` 与 `FUNDPILOT_BOOTSTRAP_PASSWORD` 初始化，并自动认领历史未归属数据。
