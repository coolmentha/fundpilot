# 平台重点转向实时行情工作台

## Goal

将 FundPilot 从「以策略执行为中心」转向「以实时行情看板为中心」，定投止盈策略降级为辅助模块。

---

## 用户决策总结

| # | 决策项 | 结论 |
|---|--------|------|
| 1 | 行情工作台内容 | 自选基金行情列表 + 大盘指数 + 涨跌排行 + K线走势图 + 板块资金流向 |
| 2 | 交易与策略关系 | 行情与交易完全分离，两个独立区域 |
| 3 | 行情范围 | 自己的基金（持仓+观察） + 全市场板块/资金流向 |
| 4 | 导航架构 | 侧边栏上下分区：上方「行情」、下方「策略」 |
| 5 | 大盘指数 | 用户自定义选择展示哪些指数 |
| 6 | K线图策略 | ETF/指数基金→跟踪指数K线(OHLCV)；主动/混合基金→净值走势图(折线) |
| 7 | 刷新频率 | 交易时段 5-10 秒高频自动刷新 |
| 8 | 板块/资金流向 | 行业板块涨跌排行 + 北向资金/主力资金流向 |
| 9 | 涨跌排行 | 仅自选基金排行（非全市场） |
| 10 | 行情区页面结构 | 单页整合：行情工作台首页包含所有行情内容 |

## Requirements

### R1: 大盘指数行情

- **R1.1** 用户在「用户配置」页可选择关注哪些指数（默认：上证指数、沪深300、创业板指）
- **R1.2** 行情工作台顶部展示指数条，每个指数显示：名称、当前点位、涨跌幅、涨跌额
- **R1.3** 指数数据交易时段 5-10 秒自动刷新
- **R1.4** 指数数据源：东方财富 push2 API（现有 `EastmoneyKlineClient` 扩展实时行情接口）

### R2: 自选基金行情列表

- **R2.1** 展示所有非 ARCHIVED 状态的基金（持仓 + 观察），列为实时行情列表
- **R2.2** 每行展示：基金代码、名称、最新净值/估算净值、涨跌幅、成交额（ETF）、持仓份额（如有）
- **R2.3** 支持按涨跌幅、成交额排序；支持切换升序/降序
- **R2.4** 盘中显示估算涨跌幅（来自 fundgz），带「估」标记；盘后切换为实际净值涨跌幅
- **R2.5** 交易时段 5-10 秒自动刷新；非交易时段显示上一交易日收盘数据
- **R2.6** 点击行进入基金详情页

### R3: 涨跌排行

- **R3.1** 在自选基金列表中支持按涨跌幅排序即为排行
- **R3.2** 不需要独立的排行页面，排行功能内嵌在行情列表中

### R4: K线/走势图

- **R4.1** 基金详情页「行情指标」Tab 增加图表区域
- **R4.2** ETF/指数基金：显示跟踪指数 K 线图（蜡烛图 + 成交量柱状图）
- **R4.3** 主动/混合基金：显示净值走势折线图
- **R4.4** K线图支持日K/周K/月K切换
- **R4.5** 图表使用轻量级前端图表库（ECharts 或 lightweight-charts）

### R5: 板块/资金流向

- **R5.1** 行情工作台展示行业板块涨跌排行（如半导体、新能源、医药等板块今日涨跌幅）
- **R5.2** 展示北向资金净流入/流出、主力资金净流向
- **R5.3** 交易时段 5-10 秒自动刷新
- **R5.4** 数据源：东方财富板块行情 API + 资金流向 API（需新增接入）

### R6: 导航重组

- **R6.1** 侧边栏从「日常/资产/系统」三组改为「行情/策略/系统」三组
- **R6.2** 「行情」组包含：行情工作台（首页）
- **R6.3** 「策略」组包含：交易信号、操作确认、我的基金
- **R6.4** 「系统」组保持不变：用户配置、管理操作、监控
- **R6.5** 首页路由 `/` 指向行情工作台（替代现有概览页）
- **R6.6** 移动端底部导航同步调整

### R7: 后端实时行情缓存

- **R7.1** 新增后端缓存层：东方财富侧 30-60s 拉一次，前端 5-10s 轮询后端缓存
- **R7.2** 缓存数据包括：基金估值（fundgz）、指数实时行情、板块涨跌、资金流向
- **R7.3** 缓存使用内存（ConcurrentHashMap + @Scheduled），不引入 Redis
- **R7.4** 交易时段（9:30-11:30, 13:00-15:00）自动刷新缓存；非交易时段休眠

### R8: 用户配置扩展

- **R8.1** 用户配置页新增「关注指数」选择器（多选）
- **R8.2** 关注指数列表持久化到 `user_config` 表

## Technical Notes

- **高频刷新 vs 限流**：东方财富 2 req/s 限流约束下，后端缓存层以 30-60s 频率拉取东方财富数据，前端以 5-10s 频率轮询后端缓存接口
- **前端图表库**：ECharts（功能全面，社区大）或 lightweight-charts（TradingView 出品，K线专用，体积小）——设计阶段确定
- **指数代码格式**：现有 `SecidFormat` 已支持 `.SH` / `.SZ` 转换，实时行情接口复用相同格式
- **缓存存储**：ConcurrentHashMap + `@Scheduled`，不引入新基础设施
- **fundgz 批量查询**：N 只基金逐个查询需 N/2 秒（2 req/s），缓存层需考虑分批拉取策略
