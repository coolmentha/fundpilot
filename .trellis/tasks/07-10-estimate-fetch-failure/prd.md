# 估值失败不复用旧缓存

## Goal

净值继续作为已结算事实正常入库；盘中估值只使用本次成功拉取且属于北京时间当天的数据。估值失败时立即失效旧估值，并让用户明确看到失败状态，禁止用旧缓存、前一交易日估值或部分全仓合计掩盖失败。

## Requirements

- `fund_nav_history` 的净值同步、当晚净值确认和增量入库逻辑保持不变。
- 估值仍只保存在进程内存，不写入 `fund_nav_history` 或其他数据库表。
- 单基金本次估值拉取成功且 `estimateTime` 属于北京时间当天时，覆盖缓存并清除该基金失败状态。
- 单基金拉取异常、空响应、解析为空或 `estimateTime` 非北京时间当天时，立即删除该基金旧估值并标记本次拉取失败。
- 当日净值已入库时，收益使用实际净值，历史估值失败状态不得覆盖实际值或向用户报错。
- 当日净值未入库且估值失败时，今日涨跌、今日盈亏、当前持仓市值和当前总盈亏不得使用上一期数据冒充当前值。
- 任一持仓基金今日盈亏未知时，全仓今日合计保持未知，不计算部分合计。
- 单基金 View 暴露估值拉取失败状态；组合汇总暴露失败的持仓基金数量。
- 总览、行情自选列表、基金管理列表和基金详情页明确显示“估值拉取失败”。

## Acceptance Criteria

- [ ] 连续两次刷新中，第一次成功、第二次返回空时，第二次后旧估值不可读取且失败状态为 true。
- [ ] 连续两次刷新中，第一次成功、第二次抛异常时，第二次后旧估值不可读取且失败状态为 true。
- [ ] 返回昨日或更早 `estimateTime` 时不进入缓存，并标记失败。
- [ ] 后续成功返回当天估值时覆盖缓存并清除失败状态。
- [ ] 当日净值已入库时，单基金和组合均使用实际值，估值失败标记不影响展示。
- [ ] 当日净值未入库且估值失败时，当前估值驱动的收益字段为空，组合今日合计为空，失败基金数正确。
- [ ] 前端四个展示面均能看到明确失败文案，不显示旧估值或旧收益。
- [ ] 后端目标测试与全量 `mvn verify` 通过，前端 `npm run build` 通过，浏览器烟测通过。

## Constraints

- 不新增依赖，不修改数据库 schema，不改变估值接口的成功数据结构。
- 市场宽度、指数、板块和资金缓存继续沿用各自现有的旧缓存降级策略；本次严格失效只适用于基金估值。
