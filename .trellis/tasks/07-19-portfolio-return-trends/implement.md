# 实施清单

1. 阅读 backend/frontend 对应 Trellis spec 和现有 controller/view/repository 模式。
2. 新增 `V24` 组合快照表及唯一业务日期约束。
3. 新增快照 entity、repository、service；复用 `PortfolioReturnService`，实现同日 upsert 和缺失估值标记。
4. 新增每日快照 job，安排在净值确认之后，并保留早间补拉后的同日更新入口。
5. 新增区间收益 API，支持预设区间和自定义日期；实现累计收益、资金流、最大回撤及数据不足状态。
6. 增加后端最小测试：重复 upsert、入金/赎回剔除、无估值、QDII 同日回补、空历史。
7. 在工作台接入区间控件、收益曲线、区间摘要和不完整提示；保留现有指数展示与 v0.9 收益元素。
8. 运行后端测试、前端构建和浏览器工作台冒烟检查。
9. 检查迁移、任务失败日志和 v0.9 接口兼容性；再进入部署审批。

## 风险与回滚点

- `V24` 迁移：只新增表，失败可停在迁移前；不删除旧表。
- 快照任务：失败只影响趋势数据，不影响交易确认和当前收益接口；可停用任务。
- 区间计算：首个快照不足时必须返回数据不足，不用默认值掩盖。

## 验证命令

- `npm --prefix frontend run build`
- 使用 Playwright 登录后检查工作台趋势区间切换和缺失估值提示。
