# 允许用户修改持仓成本价

## Goal

允许用户修正当前持仓的成本单价，使持仓收益和依赖成本价的后续业务计算使用修正后的值，避免只能在建仓时录入、录错后无法更正。

## Background

- 当前仅在新建基金并录入初始持仓时允许填写 `costPerShare`；现有基金的编辑弹窗不展示该字段。
- 当前持仓事实由 Accounting 的 Position 持有，基金列表和详情通过 Insights 查询该事实。
- `costPerShare` 会影响当前未实现盈亏、卖出纪律和智能定投等后续计算。
- FIFO lot 的 `acquireCostPerShare` 用于历史交易核算，与当前持仓成本基准是不同事实。

## Requirements

- R1：用户可在现有“编辑基金”弹窗查看并修改当前持仓成本单价，无需新增独立页面。
- R2：仅持有份额大于 0 的基金允许修改成本单价；空仓观察基金和已清仓基金不提供修改入口。
- R3：成本单价必须大于 0，前端提供即时校验，后端在信任边界执行相同业务校验并返回稳定错误码。
- R4：后端必须校验当前登录用户对组合基金的所有权，不允许修改其他用户的数据。
- R5：保存必须更新 Accounting Position 持有的当前成本事实；不得把 legacy 基金字段重新定义为事实来源。
- R6：保存成功后刷新基金列表和详情查询，使成本单价、当前总盈亏以及依赖该成本的展示使用新值。
- R7：修改成本价不得改变持仓份额、建仓时间、基金状态、交易流水或分组等无关事实。
- R8：后续买入确认继续基于修正后的当前持仓成本单价执行既有加权规则；卖出仍不改变成本单价。
- R9：修改不回写已确认交易或 FIFO lot 的取得成本，未来已实现盈亏继续按真实历史买入成本核算。

## Acceptance Criteria

- [ ] AC1：持仓基金打开编辑弹窗时显示当前成本单价，输入正数并保存后，重新打开仍显示新值。
- [ ] AC2：保存后基金列表和详情展示新成本单价，总盈亏按 `持仓份额 * (当前单位净值 - 新成本单价)` 重新计算。
- [ ] AC3：输入 0、负数或无效数字时无法保存；绕过前端直接调用接口也会得到 `COST_PER_SHARE_INVALID`。
- [ ] AC4：空仓或已清仓基金不能通过 UI 或接口修改成本单价。
- [ ] AC5：其他用户的组合基金 ID 不可被修改，响应遵循现有“资源不存在”边界。
- [ ] AC6：成本修改前后的持仓份额、建仓时间、状态和交易记录保持不变。
- [ ] AC7：修改前后的 FIFO lot 数量、剩余份额和取得成本均保持不变。
- [ ] AC8：修改后确认一笔新买入时，既有加权公式以修正后的当前成本为旧成本基准。
- [ ] AC9：相关后端测试、前端测试、lint 和构建通过。

## Out of Scope

- 修改持仓份额、建仓时间或已确认交易。
- 新增成本修改历史、审批流或撤销功能。
- 改变现有买入加权、卖出不改成本和清仓再入场覆盖成本的规则。
- 批量修改多只基金的成本单价。
