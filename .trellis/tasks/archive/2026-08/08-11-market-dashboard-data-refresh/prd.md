# 优化行情工作台数据展示

## Goal

让行情工作台优先回答“市场现在怎样、组合今天表现怎样、哪些持仓贡献最大、行业资金与涨跌如何”，并明确展示行情状态和最后成功快照时间，避免旧缓存被误认为实时数据。

## Requirements

### REQ-001 市场状态与时效

- 工作台顶部展示 A 股市场状态和后端最后成功行情快照时间。
- 市场状态区分盘前、交易中、午间休市、已收盘和非交易日，并使用现有交易日历判断。
- 快照时间来自指数、市场宽度、行业数据成功刷新时间，不得使用前端轮询时间；相关数据不完整时不得伪造时间。

### REQ-002 组合总览与市场宽度

- 保留总持仓市值、今日收益、全仓涨跌幅、累计盈亏。
- 市场宽度展示上涨、平盘、下跌、涨停、跌停家数。
- 平盘使用东方财富 `f106`，任一固定市场字段缺失时保留旧完整快照。

### REQ-003 指数行情

- 保留指数点位和涨跌幅。
- A 股指数优先展示成交额；成交额不可用时回退展示涨跌额。
- 指数条与顶部状态共同表达行情时效，不增加浏览器直连外部行情源。

### REQ-004 持仓表现

- 持仓表展示基金、持仓市值、累计收益率、今日涨跌、今日盈亏、估值或确认净值及时间。
- 默认按今日盈亏贡献从高到低排序。
- 工作台展示今日最大贡献和今日最大拖累；没有可计算持仓时显示中性空值。
- 移除持仓表内重复的仓位列和仓位构成侧栏。

### REQ-005 行业表现

- 行业数据一次拉取完整行业范围，不再只使用涨幅前 20 名。
- 合并原“行业板块涨跌”和“主力资金流向”为一个行业表现模块。
- 支持按涨跌幅、成交额、主力净占比切换排序，并展示行业、涨跌幅、成交额、主力净额、主力净占比。
- 主力净占比按 `mainforceNet / turnover` 计算；成交额为空或零时显示未知。
- 不再展示由部分行业相加得到的“板块主力净额”。

### REQ-006 页面去重

- 移除重复的持仓涨跌分布和待处理操作状态条；待处理数量继续由现有导航徽标承担。
- 不新增依赖，不改变交易、估值和收益计算规则。

## Acceptance Criteria

- [x] AC-001：顶部状态使用交易日历和北京时间正确区分五种市场状态，时间来自后端成功快照。
- [x] AC-002：市场宽度完整展示上涨、平盘、下跌、涨停、跌停，旧 Redis 缺新字段时不恢复残缺快照。
- [x] AC-003：指数有成交额时展示成交额，无成交额时展示涨跌额。
- [x] AC-004：持仓表字段、默认排序和最大贡献/拖累与现有组合收益结果一致。
- [x] AC-005：行业列表覆盖完整返回范围，三种排序可切换，主力净占比计算和未知值处理正确。
- [x] AC-006：工作台不再展示重复仓位、持仓涨跌分布、待处理状态条或误导性的板块主力净额。
- [x] AC-007：后端定向测试、前端测试、lint、构建及桌面/移动端明暗主题预览验证通过。

## Constraints

- 不新增、升级或替换依赖。
- 保持现有 API 字段兼容；新增字段对旧前端可忽略。
- 外部行情失败继续保留旧缓存，但快照时间不得更新。
- 本任务不修改投资策略、收益算法、交易会计或导航结构。

## Out Of Scope

- 新行情供应商、全市场资金总额或北向资金替代源。
- 买入建议、基准比较、回测或参数优化。
- 工作台以外页面的视觉重构。
