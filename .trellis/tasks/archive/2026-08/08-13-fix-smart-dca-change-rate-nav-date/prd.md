# 修正智能定投涨跌幅净值口径

## Goal

使智能定投 `CHANGE_RATE` 模式与支付宝确认口径一致：执行日不使用当日净值或盘中估值，
仅以严格早于定投业务日的最近一期已确认单位净值，与当前平均持仓成本计算涨跌幅和本期金额。

## Background

- 当前事实网关调用 `PublishedNavApi.latest(productId)`，没有使用已经传入的 `businessDate` 截断净值。
- 常规任务在北京时间 14:55 执行，而当日净值通常在 20:00 后入库，因此正常调度往往碰巧使用上一期净值；
  当同一业务日在净值入库后补执行或手动调用时，会错误使用当日确认净值。
- 盘中实时估值没有进入该策略，问题仅是已确认净值缺少业务日上界。

## Requirements

- `CHANGE_RATE` 只读取 `navDate < businessDate` 范围内最近一期已确认单位净值。
- “上一确认估值”按最近可用确认净值解释，不要求自然日恰好是昨天；休市、节假日和净值延迟时继续向前取最近一期。
- 当日及未来净值即使已经入库，也不得参与本次定投金额计算。
- 净值缺失时继续使用现有 `NAV_UNAVAILABLE` 跳过语义，不降级为固定金额。
- 保持 `ALIPAY_2025_06_V1` 的涨跌幅公式、金额档位、两位金额舍入、成本价来源和执行幂等行为不变。
- 复用现有 `PublishedNavApi.history(..., endExclusive)` 能力，不新增依赖、数据库迁移或公共 API。

## Acceptance Criteria

- [x] 业务日之前存在多期净值时，选中其中日期最新的一期，并以其单位净值计算涨跌幅。
- [x] 业务日当日净值已经入库时，该净值被排除，执行记录的 `dataDate` 为上一期确认净值日期。
- [x] 业务日前没有确认净值时，本期记录 `NAV_UNAVAILABLE`，且不创建交易。
- [x] 现有智能定投策略和执行测试通过；新增日期边界回归测试通过。

## Out Of Scope

- 不调整涨跌幅档位、成本价算法、调度时间或前端展示。
- 不接入支付宝接口，不使用盘中估值，不修改历史执行记录。
- 不新增数据库查询方法；若现有历史查询经验证存在性能问题，再单独评估。
