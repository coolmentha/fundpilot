# 修复盘后重启估值回退

## Goal

修复生产环境在交易日盘后、当日净值尚未公布时重启后端，因基金估值缓存为空而把 T-1 对 T-2 的昨日收益展示成今日全仓收益的问题。保证今日净值未落库时优先使用 fundgz 今日估值，同时不恢复阻塞启动线程的逐基金外部请求。

## Background

- `v0.5.16` 于北京时间 15:20 后部署，`ApplicationReadyEvent` 只预热指数、板块和资金，不预热基金估值。
- 基金估值的 30 秒任务只在交易日 9:30-15:00 执行，因此盘后重启后缓存不会再填充。
- `DailyChangeResolver` 在今日净值未落库且估值缓存为空时回退到最近两期落库净值，即 T-1 对 T-2，与 `CONTEXT.md` 和 ADR-0008 的今日语义冲突。

## Requirements

### R1 启动后异步预热今日基金估值

- 应用启动完成后必须在后台刷新全部未软删基金的 fundgz 估值缓存。
- 逐基金请求不得阻塞 Spring Boot 启动完成和健康检查。
- 必须复用现有 `@EnableAsync`、`FundEstimateService` 和共享限流，不新增依赖或无边界线程池。
- 指数、板块和资金的现有启动预热行为保持不变。

### R2 禁止用昨日涨跌冒充今日涨跌

- 北京时间 9:30 之后、今日净值尚未落库且估值缓存缺失时，不得使用 T-1 对 T-2 作为今日涨跌。
- 数据暂不可用时返回未知值，不能返回昨日收益或伪造 0 作为已确认今日收益。
- 盘前 0、盘中/待公布估值、盘后实际净值三态契约保持不变。

### R3 保持全仓收益口径

- 今日净值未公布且估值可用时，`/api/portfolio/summary` 必须使用 fundgz 今日估值计算 `dailyPnlTotal`，并标记 `isEstimated=true`。
- 当日净值落库后仍切换为实际累计净值计算，不继续使用估值。

## Constraints

- 不新增或升级依赖。
- 不修改数据库 schema、CI/CD、部署或认证配置。
- 不在 GET 请求链路逐基金调用外部接口。
- 不恢复同步阻塞的启动期逐基金估值刷新。

## Acceptance Criteria

- [ ] AC1 交易日 15:20 重启时，健康检查不等待全部基金估值请求完成，后台仍会逐基金填充缓存。
- [ ] AC2 今日净值未落库且缓存有估值时，全仓今日收益使用今日估值并带估算标记。
- [ ] AC3 今日净值未落库且估值获取失败时，不再返回 T-1 对 T-2 的昨日涨跌。
- [ ] AC4 今日净值已落库时继续使用今日/昨日累计净值计算实际收益。
- [ ] AC5 聚焦测试、后端完整 CI、前端构建通过；推送后持续关注 GitHub Actions 和 tag 部署结果。
