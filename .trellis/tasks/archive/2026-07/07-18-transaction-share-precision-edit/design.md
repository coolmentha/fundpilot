# 份额精度与未确认流水编辑设计

## 边界

- 份额列统一为 `NUMERIC(19,2)`，Java 写入边界统一 `HALF_UP`；确认时严格超卖校验不变。
- 新增 PENDING 流水更新能力，不新增表或依赖。
- CONFIRMED、CANCELLED、调整交易保持不可编辑。

## API 与状态

- 新增 `PUT /api/transactions/{id}`，请求复用交易输入字段：`amount`、`shares`、`tradeDate`。
- 服务在事务内锁定交易并再次判断 `status=PENDING`，避免编辑与确认并发覆盖。
- 买入类只接受正数金额；卖出类只接受正数份额；来源、基金和关联 ID 均不从请求修改。
- 转换转入腿不允许直接编辑；编辑转出腿的交易日期时同步转入腿，份额只写转出腿。
- 信号与定投关联原样保留，更新不触碰来源计划。

## 全量卖出

- 前端“全部”读取已经统一为两位的 `FundView.holdingShares` 并写入表单。
- 提交后 PENDING 流水冻结该数值；后续新增持仓不自动加入。
- 确认时继续锁基金并严格比较事实持仓；事实持仓减少时返回现有 `INSUFFICIENT_HOLDING_SHARES`。

## 前端

- 份额输入、展示和提交固定 2 位；点击“全部”直接提交当前两位事实持仓。
- 抽取一个轻量的 PENDING 编辑弹窗，供基金详情交易流水与全局确认页复用。
- 只有 PENDING 主记录显示编辑按钮；转换派生转入腿不显示。
- 更新成功后失效交易、基金、待处理和组合相关查询。

## 兼容与回滚

- 新增 Flyway V23，将 transaction/lot/redemption 份额列舍入为两位，并把 `UNIT_NAV_V1` 重建状态重置为 PENDING。
- 应用启动复用 `AccountingRebuildService` 重建 lot、赎回明细、成本和状态；失败阻止启动。
- 迁移前由部署流水线完成数据库备份；回滚需恢复备份，不能只回滚镜像。
