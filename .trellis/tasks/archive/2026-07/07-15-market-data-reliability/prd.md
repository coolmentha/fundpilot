# 修复行情数据可靠性与请求性能

## Goal

让行情相关请求在外部数据源抖动时快速、可解释地降级，并保证普通基金及净值滞后型基金的新公布净值能够及时入库，不再把“不支持估值”“尚未公布”和“调用失败”统一显示为系统故障。

## Background

- 前端请求统一在 15 秒后取消，但后端手工构建的 Feign 客户端沿用连接 10 秒、读取 60 秒默认值，串行数据源链会放大总等待时间。
- `DailyNavConfirmService` 只有在 `fundgz.jzrq == 今天` 时才拉 `pingzhongdata`，导致 FOF/QDII 等净值天然滞后的基金无法在新净值公布当晚入库（
  `DailyNavConfirmService.java:83-88`）。
- 净值解析每次创建 GraalVM JavaScript Context 并执行完整脚本（`EastmoneyJsParser.java:31-32`）；实测单只基金网络下载约
  83ms，而 Java 真实调用约 2.51s。生产镜像明确使用普通 Temurin JRE 解释器模式（`backend/Dockerfile:16,29`）。
- 当前“同花顺降级源”解析器全部抛 `UnsupportedOperationException`，不是可工作的备用源（`ThsJsParser.java:20-39`）。
- 估值空响应、产品不支持、非当天数据、超时和解析异常最终都进入同一个 `estimateFetchFailed` 布尔状态（
  `FundEstimateService.java:32-41`、`MarketRealtimeCache.java:245-280`）。
- 代表性外部源验证：普通股票/指数/债券净值结构可解析；FOF/QDII 净值日期可滞后 1-2 天；货币基金没有当前解析器要求的净值数组；REIT
  样本数组长度不一致且 fundgz 返回空数据。

## Requirements

### REQ-001 端到端超时预算

- 所有外部行情客户端必须显式配置短连接、短读取超时。
- 单个在线请求不得因串行降级超过前端 15 秒预算；超时后不得继续占用请求线程执行分钟级外呼。
- 自动重试仅允许覆盖明确的瞬时传输错误，并计入统一总时间预算。

### REQ-002 净值确认与估值解耦

- 晚间净值确认不得依赖 fundgz 是否提供盘中估值。
- 对未确认基金，应以 `pingzhongdata` 中“是否存在晚于数据库最新日期的净值”为入库依据，而不是强制净值日期等于北京时间今天。
- FOF/QDII 等滞后型基金的新公布净值必须能够按实际净值日期入库。
- 同一净值日期重复轮询必须保持幂等。

### REQ-003 估值结果可解释

- 估值结果至少区分：可用、不支持/空数据、非当天或尚未开始、调用超时、响应解析失败。
- 只有真实调用失败才允许前端显示“估值拉取失败”；产品不支持或当前无估值时显示中性不可用状态。
- 当日实际净值已入库后，不再受估值失败状态影响。

### REQ-004 净值解析性能

- 净值和基金字典的已知 JS 字面量必须通过受限结构提取后使用结构化 JSON 解析，不再执行远端 JavaScript。
- 保持现有普通基金净值和基金字典解析结果兼容。
- 解析器必须对空字段、数组长度不一致和不支持的数据形态给出明确结果，不得静默伪装成外部调用失败。

### REQ-005 数据源降级真实性

- 同花顺必须实现为真实可用的降级源，不得保留猜测路径或占位解析器。
- 同花顺各 operation 的支持范围必须以无需登录、可重复验证的公开接口为依据；不支持的 operation 必须显式标记
  unsupported，不得伪装成已实现。
- 数据源链必须区分不支持、空结果和真实失败，日志应能识别实际尝试的数据源与失败类型。
- 本次不得新增依赖；优先复用现有 Feign、Jackson、Micrometer 与 Spring 调度能力。

### REQ-006 后台任务资源边界

- 外部网络等待不得被数据库事务包裹。
- 30 秒实时刷新任务不得重入；基金数量增加或外部源变慢时，不得无限堆积。
- 普通缓存 GET 接口继续只读本地内存/数据库，不直接击穿外部源。

### REQ-007 可观测性

- 按数据源、操作、结果记录外部调用次数与耗时，至少能区分 success/timeout/empty/unsupported/parse_error。
- 定时任务耗时指标必须在现有 Prometheus/Grafana 配置下可查询。
- 日志不得包含凭据或完整外部响应正文。

## Acceptance Criteria

- [ ] AC-001：模拟单源超时时，在线请求在前端 15 秒预算内返回可识别错误或本地降级结果。
- [ ] AC-002：fundgz 返回空或超时时，`pingzhongdata` 出现比数据库更新的净值仍会入库。
- [ ] AC-003：FOF/QDII 样例的新净值日期早于“今天”时仍能正确增量入库。
- [ ] AC-004：不支持估值的基金不会显示“估值拉取失败”，真实超时仍显示失败。
- [ ] AC-005：普通基金净值、基金字典、空响应和数组异常解析测试全部通过，解析过程不创建 GraalVM Context。
- [ ] AC-006：主数据源失败时，同花顺真实接口能够分别返回兼容的净值历史、基金字典和指数 K 线；无数据的指数明确返回
  empty，不产生伪造行情。
- [ ] AC-007：实时刷新慢于 30 秒时不会并发重入，数据库事务不覆盖外部请求等待。
- [ ] AC-008：外部调用指标包含 source/operation/result，且现有 job 耗时查询能够返回数据。
- [ ] AC-009：后端相关单元/集成测试、前端状态测试、构建和代表性 live smoke 验证通过。

## Constraints

- 不新增、升级或替换依赖。
- 不修改公共业务 API 的既有成功响应字段语义；新增状态字段需保持前端兼容。
- 不在本任务中修改投资策略、仓位或交易会计规则。
- 生产 Caddy 配置不在仓库内，本任务只处理应用内超时和仓库内 Nginx 配置。

## Out Of Scope

- 引入新的第三方行情供应商或付费数据源。
- 完整重做基金产品分类体系。
- 为货币基金实现万份收益/七日年化等不同于净值涨跌的收益模型。
- 为 REIT 单独建立收益、估值或交易模型。

## Scope Decision

- 用户确认本次暂不支持货币基金和 REIT 的不同收益数据结构；遇到这两类不兼容数据时使用中性“暂无数据/当前不支持”语义，不显示为真实外部调用失败。
