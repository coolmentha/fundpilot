# 总览增加全市场涨跌家数

## Goal

在行情工作台顶部“总览”中展示当前沪深京股票市场的上涨、下跌家数，帮助用户在查看组合收益时同时判断市场整体宽度。

## Confirmed Facts

- 当前总览由 `frontend/src/components/PortfolioOverview.jsx` 渲染，仅包含全仓收益、上涨基金数、下跌基金数。
- 实时行情统一由 `MarketRealtimeCache` 每 30 秒刷新，前端请求只读内存缓存，不得在请求链路直连东方财富。
- 2026-07-10 实测东方财富 `ulist.np/get` 的 `f104`、`f105`、`f106` 可分别返回上涨、下跌、平盘家数。
- 上证指数 `1.000001`、深证成指 `0.399001`、北证 50 `0.899050` 的上述字段分别覆盖沪市、深市、北交所当日有涨跌状态的股票；三者相加得到沪深京市场宽度，不等同于全部上市股票总数。

## Requirements

- R1: 市场宽度固定汇总 `1.000001`、`0.399001`、`0.899050`，不得依赖用户自选指数配置。
- R2: 后端通过现有指数实时批量请求同时获取 `f104`、`f105`，不得为市场宽度增加一次独立外部请求。
- R3: 市场宽度写入独立内存缓存，并通过 `GET /api/market/breadth` 只读接口返回 `risingCount`、`fallingCount`。
- R4: 任一市场数据缺失或解析失败时不得发布部分汇总；保留上一份有效缓存。首次启动无有效缓存时返回空数据，由前端显示 `-`。
- R5: 总览新增一张“大盘涨跌”进度条卡片，左侧红色表示上涨、右侧绿色表示下跌，并在两端显示实际家数。
- R6: 进度条比例按 `上涨家数 / (上涨家数 + 下跌家数)` 与 `下跌家数 / (上涨家数 + 下跌家数)` 计算，平盘不计入比例；涨跌合计为 0 时显示空轨道，不伪造比例。
- R7: 现有基金计数改为“上涨基金”“下跌基金”，避免与股票涨跌家数混淆。
- R8: 桌面、平板和手机布局均不得溢出或遮挡；不新增前端或后端依赖。

## Acceptance Criteria

- [x] 用户未配置任何自选指数时，总览仍可显示沪深京上涨、下跌家数。
- [x] 后端只使用一次指数批量请求，同时刷新自选指数缓存和市场宽度缓存。
- [x] 三个市场数据完整时，接口返回的上涨/下跌家数等于三个市场对应字段之和。
- [x] 任一市场或计数字段缺失时，不返回部分合计，并保留旧缓存。
- [x] 总览明确区分基金涨跌数量与沪深京股票涨跌数量，市场宽度以左红右绿进度条展示，颜色占比与涨跌比例一致。
- [x] 涨跌合计为 0 或数据不可用时，进度条不展示误导性比例，且不影响已有组合总览展示。
- [x] 后端相关单元测试通过，前端生产构建通过。

## Out Of Scope

- 平盘股票家数展示及其在进度条中的占比。
- 市场宽度历史曲线、分钟级趋势和数据库持久化。
- 按沪市、深市、北交所分别展示明细。
