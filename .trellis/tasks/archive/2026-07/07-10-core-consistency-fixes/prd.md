# 修复核心交易与行情一致性问题

## Goal

修复生产环境中交易确认日期、信号回应、基金状态、ETF 逻辑止损、初始持仓 lot 和实时行情日期口径的核心一致性缺陷，确保交易、行情与策略使用同一事实来源。

## Requirements

### R1 交易确认使用交易自身日期

- `NavConfirmJob` 必须按北京时间计算前一自然日对应的 UTC 00:00 日期标签，不能受 JVM UTC `Clock` 影响而偏一天。
- 批量确认优先使用每笔 PENDING 交易的 `createdDate` 推导交易日期；任务参数只作为历史空日期的降级值。
- 周末后补确认仍使用原交易日净值，不得用下一交易日净值确认旧交易。

### R2 信号回应必须归属正确且幂等

- `POST /api/funds/{fundId}/operations` 必须校验路径基金与 `signalLogId` 所属基金一致。
- 同一 SignalLog 最多生成一笔未软删交易，并发请求也不能重复生成。
- 待确认信号只返回“非 NONE 且尚无对应交易”的 SignalLog。
- 所有由信号触发的交易，包括 SELL，必须保留 `signal_log_id`。

### R3 基金状态以已确认事实持仓为准

- 创建 PENDING 交易时不得提前把基金改为 `HOLDING` 或 `CLEARED`。
- 买卖交易确认后统一按 CONFIRMED 事实份额重算状态：无已确认交易为 `PENDING_HOLDING`，正持仓为 `HOLDING`，已清仓为 `CLEARED`。
- 撤销 PENDING 交易后执行同一状态重算，修复可能遗留的提前状态变更。

### R4 ETF 逻辑止损输入完整

- 跟踪指数 `VolumeState.HIGH_DROP` 必须映射为“放量且当日收跌”，不能把 `benchmarkDroppedToday` 固定为 false。
- 真实 `MarketIndicatorSnapshot -> MarketIndicators -> DisciplineStrategyService` 调用链必须有回归测试。

### R5 初始持仓生成可赎回 lot

- 初始持仓同步确认后必须创建对应 `fund_lot`，份额、建仓日期和成本单价与交易一致。
- 未填写 `openedAt` 时使用当前时间作为 `openedAt` 和 `confirmTime`，不得产生无日期的 CONFIRMED 买入交易。
- 初始持仓是历史盘点，不重复扣申购费。

### R6 实时行情日期与观察池一致

- 交易日判断和“今日净值已确认”判断统一使用北京时间自然日映射到 UTC 00:00 日期标签。
- 基金估值缓存覆盖全部未软删基金，观察池基金也能使用盘中三态涨跌。

### R7 14:50 行情与信号严格串行

- 第三批行情抓取完成后才能生成当日信号，不能依赖两个同秒 cron 的不确定执行顺序。
- 手动行情刷新和手动信号生成入口保持可用。

### R8 交易日历日常增量同步

- 日常和启动同步只对数据库当前最大日期之后的交易日执行写入。
- 空表时执行全量初始化。
- 管理接口保留全量补写能力，用于人工修复缺口。

### R9 启动线程不得执行逐基金外部刷新

- `ApplicationReadyEvent` 只允许预热批量行情，不逐基金拉 fundgz 估值或费率 HTML。
- 基金估值由交易时段 30 秒任务刷新。
- 基金费率改为北京时间 02:30 刷新，必须早于 03:00 交易确认。

### R10 最短持有期只由买入重置

- 最近买入时间只查询 CONFIRMED 的 INCREASE/TRANSFER_IN/INVEST。
- SELL、ADJUST 和 PENDING 交易不得重置 `MIN_HOLD_DAYS`。
- 无买入确认记录时不得中断信号生成，按已满足持有期处理。

## Constraints

- 不新增或升级依赖。
- 不修改数据库 schema。
- 不修改 CI/CD、部署和认证配置。
- 不删除或弱化有效测试。
- 本任务先处理 P0/P1 正确性问题；N+1、前端拆包、同花顺占位和规范性批量整改另行处理。

## Acceptance Criteria

- [ ] AC1 北京时间周二 03:00 运行时确认日期为周一 UTC 00:00；周一运行可按交易 `createdDate` 确认上周五交易。
- [ ] AC2 错误路径基金、重复确认和并发重复确认均被拒绝，同一 SignalLog 只有一笔交易。
- [ ] AC3 已回应信号不再出现在待确认列表，SELL 交易保留 `signalLogId`。
- [ ] AC4 全额卖出在 CONFIRMED 后状态为 `CLEARED`；撤销 PENDING 卖出不改变事实状态。
- [ ] AC5 ETF 指数放量下跌时真实映射链可触发 `LOGIC_BROKEN`。
- [ ] AC6 初始持仓创建一条 open lot，未填 `openedAt` 时交易确认时间非空。
- [ ] AC7 周一实时行情任务查询周一交易日；北京时间 00:00-08:00 不把昨日净值认作今日净值。
- [ ] AC8 观察池基金进入估值缓存；第三批行情完成后才调用信号生成。
- [ ] AC9 日历非空时只写最大日期之后的数据；管理全量同步仍可补写历史缺口。
- [ ] AC10 聚焦测试、后端完整 CI、前端构建通过；推送后持续跟踪 GitHub Actions 直到全绿。
- [ ] AC11 启动事件不执行逐基金估值/费率请求；费率刷新早于 03:00 确认任务。
- [ ] AC12 较新的卖出不覆盖最近买入时间；无买入记录仍能生成并落库信号。

## Notes

- 当前生产版本基线：`e8b3a3a` / `v0.5.15`。
- 本任务修正上一轮“前一日 UTC 00:00”实现未考虑生产 cron 运行时区的问题，并同步更新项目规范防止重复。
