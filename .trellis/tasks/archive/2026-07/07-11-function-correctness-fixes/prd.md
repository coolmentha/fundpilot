# 核心功能正确性修复

## Goal

以 `CONTEXT.md` 为当前产品基准，修复信号重跑、定投日历、交易发生日和输入校验中的数据正确性问题，避免重复交易、漏定投和错误净值确认。

## Requirements

- R1：同一基金同一交易日的信号已经生成交易后，管理员重跑信号不得覆盖原信号或生成新的待回应信号。
- R2：周定投只允许周一至周五；月定投遇连续非交易日时可跨月顺延到下一个交易日。
- R3：同一定投计划同一北京时间自然日只允许自动生成一笔交易，交易已确认或撤销后重跑也不得再次生成。
- R4：手动交易允许填写交易发生日；为空时默认当前时间；自动和手动确认继续按该发生日查累计净值。转换两腿使用同一交易发生日。
- R5：后端校验定投金额、频率、周/月日期范围，以及信号实际金额/份额必须为正数，非法输入返回业务错误。
- R6：策略正常生效但当天未满足卖出条件时，信号原因不得显示“无生效策略”。
- R7：修正“最新净值”“每日 21:00”“仅 EFFECTIVE 基金刷新”等与当前实现不一致的界面文案。

## Acceptance Criteria

- [x] 已回应的逻辑止损信号重跑后仍只有原交易，不出现新待回应信号。
- [x] 月计划日落在月末休市区间时，下月首个交易日能够补执行。
- [x] 周定投无法选择或提交周六、周日。
- [x] 已确认或已撤销的当日定投交易存在时，任务重跑不新增交易。
- [x] 补录历史交易后，确认使用用户选择日期对应的净值。
- [x] 非正金额/份额和非法定投配置均返回明确业务错误。
- [x] 生效策略未触发卖出时显示“未触发卖出条件”。
- [x] 前后端测试、lint 和构建全部通过。
