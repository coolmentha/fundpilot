# 基金分组技术设计

## 数据模型

- 新增 `fund_group`：名称、排序值及通用审计字段；有效名称使用 `lower(name)` 唯一索引。
- 新增 `fund_group_member`：`fund_id + group_id` 唯一，外键级联清理关联。
- 现有基金无需回填，迁移后自然处于无分组状态。

## 后端契约

- `GET /api/fund-groups`：按排序返回全部分组及关联基金数量。
- `PUT /api/fund-groups`：事务性接收管理弹窗的完整分组草稿；完成新增、重命名、删除和排序。删除只清理关联，不删除基金。
- `FundCreateRequest` 增加可选 `groupNames`；服务层统一 trim、校验、大小写不敏感解析并按需创建。
- `FundView` 增加 `groups`，供两个现有列表本地筛选和展示。
- 新错误码覆盖名称非法、重复和未知分组草稿项。

## 前端交互

- 基金管理页与首页持仓使用 Ant Design `Tabs`，固定“全部”在首位，一次选择一个分组。
- 基金管理表增加分组列；无分组显示 `-`。
- 新建/编辑表单使用可创建选项的多选控件。
- 管理弹窗维护本地草稿；保存时一次提交，取消时丢弃。
- 拖拽使用 `@dnd-kit/core` 与 `@dnd-kit/sortable`，支持鼠标、键盘和触控。

## 兼容与回滚

- API 新字段均为附加字段，现有基金请求不传 `groupNames` 时保持无分组或更新时保持现状，具体合并语义由服务层显式区分。
- 数据库迁移只新增表和索引，不改已有业务表数据。
- 发布失败沿用现有生产备份与自动回滚流程。

## 风险

- 批量保存必须在单事务中校验完毕后写入，避免部分重命名或删除。
- 名称唯一性既由服务层给出友好错误，也由数据库索引兜底并发冲突。
- 删除当前选中的分组后，前端筛选自动回到“全部”。
