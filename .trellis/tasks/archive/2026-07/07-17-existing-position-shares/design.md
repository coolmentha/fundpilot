# 已有持仓按份额录入设计

## 接口与边界

- `FundCreateRequest.initialMarketValue` 替换为 `initialHoldingShares`。
- 前端创建表单同步替换字段，不提供旧字段兼容层。
- 数据库实体不新增字段：事实持仓仍来自已确认交易份额聚合。

## 数据流

1. 用户选择录入已有持仓并填写份额、成本单价、建仓日期。
2. 后端拉取并读取最近确认单位净值。
3. 初始交易直接保存用户份额，`nav` 保存最近确认单位净值，`amount = shares × nav`。
4. 基金成本单价保存用户输入值；缺省时使用最近确认单位净值。
5. 页面当前市值继续由 `holdingShares × 当前净值或估值` 派生。

## 兼容性

- 这是创建基金请求字段的破坏性替换，前后端在同一次发布中更新。
- 不修改存量数据库记录和现有交易结构。
- 普通手动交易 API 不受影响。

## 风险与回滚

- 风险：前后端版本不一致时已有持仓字段无法识别，因此必须同步部署。
- 回滚：同时恢复前后端旧字段和金额反推逻辑；无 schema 回滚。
