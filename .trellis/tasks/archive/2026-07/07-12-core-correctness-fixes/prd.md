# 修复核心业务正确性与信号生命周期

## Goal

修复会导致错误止盈、自动定投漏单、账实状态不一致和过期信号误执行的问题，并清理仍向用户暴露的旧金字塔产品语义。

## Background

- `market_indicator_snapshot.current_nav` 是累计净值，当前止盈逻辑却用它与单位成本价比较，违反 ADR-0019。
- `DcaSuggestionJob.run()` 同 Bean 调用 `@Transactional generateForFund()`，生产调度路径绕过事务代理。
- `ADJUST_IN/ADJUST_OUT` 录入即确认，但没有重算基金状态；`ADJUST_OUT` 还允许事实份额变为负数。
- 行情定时任务只按周一至周五运行，没有交易日历门控。
- 未回应信号没有过期或忽略语义，旧卖出建议仍可执行。
- `PRODUCT.md`、`CONTEXT.md`、确认页和设置页仍有已退役的 BUILD/ADD、金字塔、回测和总可投资资金语义。
- 本地后端测试默认连接开发库，固定日期夹具会被历史数据污染。

## Requirements

### R1 止盈双净值口径

- 止盈整体收益、浮盈金额和建议卖出份额必须使用单位净值。
- 止盈周期峰值和从峰值回撤必须继续使用累计净值。
- 任一所需净值缺失或非正时不得回退到另一口径，应禁用本次止盈评估。
- 历史 `cyclePeakNav` 保持累计净值语义，不做数据迁移。

### R2 自动定投事务

- 每只基金的定投生成必须经过 Spring 事务代理。
- 单只基金失败不得阻断其他基金。
- 同计划同一北京时间自然日的数据库幂等约束保持不变。

### R3 账实调整一致性

- ADJUST 交易确认、lot 更新和基金状态重算必须处于同一事务。
- `ADJUST_OUT` 不得超过当前 CONFIRMED 事实持仓。
- 合法的未跟踪 `ADJUST_IN` 份额仍允许在 ADJUST_OUT 时按零费用事实调整，不得误报 lot 缺口。
- 并发 ADJUST 操作需通过基金行锁串行化，避免两个请求同时通过旧持仓校验。

### R4 交易日门控

- 三批自动行情抓取在非交易日均跳过。
- 非交易日不得自动或通过管理信号入口生成 SignalLog。
- 管理员手动刷新行情仍可用于诊断，但信号生成必须受业务层二次门控。

### R5 信号生命周期

- 普通信号仅在当前日期之前最近一个 A 股交易日有效；周末仍允许处理周五信号。
- 当前策略明确绑定的 `TRIGGERED` 定投止盈信号持续有效，直到确认、撤销或忽略。
- 历史信号需要区分无需操作、待回应、已回应、已忽略和已过期。
- 用户可忽略待回应信号；忽略当前止盈信号时，止盈周期恢复到 `ARMED`，不得卡死在 `TRIGGERED`。
- 已忽略或已过期信号不得确认；已忽略信号不得被同日重跑覆盖。

### R6 前端操作闭环

- 确认页以 SELL 为当前主流程，删除常态 BUILD/ADD 和档位说明，但保留历史数据兼容。
- 卖出输入展示当前持仓，限制最大份额，并提供按建议和全部卖出快捷操作。
- 待确认接口失败时显示持久错误态，不得伪装成空列表。
- 历史信号展示生命周期状态；忽略后待确认列表立即刷新。

### R7 文档与测试基础

- `PRODUCT.md` 和 `CONTEXT.md` 必须以行情工作台、自动定投、SELL 卖出纪律为当前模型。
- 设置页不得提供可任意覆盖的旧“总可投资资金”配置；V20 只允许通过正数外部入金累加总资金池。
- 资金流向文档以当前行业板块主力资金实现为准，北向接口作为遗留能力单独处理。
- 后端测试不得默认连接或清理开发业务 schema；本地无 Docker 时仍应有可运行的隔离方案。
- 本任务不修改 CI/CD；如需调整 `.github/workflows` 必须另行确认。

### R8 全站 API 鉴权

- 所有 `/api/**` 端点必须校验有效会话 Cookie 或管理员 API Key，缺失或错误凭据返回 401。
- 未配置服务端 API Key 时必须失败关闭，不得回退为匿名访问。
- 浏览器只在登录请求 Header 中提交一次主 Key，后端签发 30 天 HttpOnly HMAC 会话；主 Key 不进入 URL、请求体、日志、浏览器存储、Cookie
  或构建产物。
- 脚本与部署探活可继续使用 Header；静态资源、Actuator 和定时任务不受业务 API 鉴权影响。

### R9 Flyway 严格校验与遗留 V7 修复

- 删除全局 `*:missing`，任意未知缺失迁移必须阻止应用启动。
- 仅在显式开启修复开关时允许处理历史 `V7__dca_take_profit_replaces_timing.sql` 的 Missing 记录。
- repair 前必须确认唯一 Missing 为已知 V7，且不存在 checksum、description、type 或失败迁移异常。
- repair 结果必须只删除该 V7 记录；随后继续严格 migrate/validate。

### R10 前端 CI 门禁

- 前端 CI 在 build 前必须依次执行 `npm run lint` 和 `npm test`。
- 任一 lint、test 或 build 失败均阻止 CI 通过。

### R11 可回滚部署

- 发布脚本必须使用不可变 `v*` tag，并保存上一成功部署 tag。
- 数据库备份、发布、健康检查和回滚必须在同一个远程脚本中完成。
- 部署期间停止前后端写入，生成并校验 PostgreSQL custom-format 备份。
- 候选新版本健康检查失败时恢复部署前数据库备份和上一版本镜像，并再次验证健康状态。
- 发布状态提交后的正常模式或公网检查失败时停止应用并报错，不得恢复数据库覆盖已产生的新写入。
- 首次部署无上一版本时仍恢复数据库，但保持应用停止并明确失败。

### R12 卖出信号互斥与逻辑止损强约束

- `LOGIC_BROKEN` 回应必须按锁内重新计算的 CONFIRMED 事实持仓一次清空，不接受任意部分份额。
- 新的 `LOGIC_BROKEN` 信号必须取代尚未回应的 `TRIGGERED` 止盈信号，旧止盈不得继续可执行。
- 同一基金任一时刻不得同时存在两个可执行 SELL 信号。

### R13 交易业务日期一致性

- FIFO lot 的申购日和赎回日必须按北京时间自然日计算持有天数。
- 手工交易、自动交易和历史补录不得因 UTC 截日产生一天的赎回费档位误差。
- 持仓建仓时间与最近买入窗口优先使用业务 `tradeDate`，仅存量缺失时才回退确认时间。

### R14 持久登录安全与故障恢复

- 启动重验仅在明确的 401/`ADMIN_UNAUTHORIZED` 时回到登录页；断网、超时和 5xx 必须保留 HttpOnly 会话并允许重试。
- 所有认证请求必须有统一截止时间；恢复失败时不得永久阻塞在加载动画。
- 主动退出必须同步到同源其他标签页。
- 生产静态响应必须设置严格 CSP；主 Key 不得持久化到任何脚本可读存储。

### R15 归档、配置与定投并发一致性

- 存在 PENDING 交易的基金不得归档，跨基金转换不得被拆成孤立单腿。
- 归档必须覆盖基金拥有的 DCA、lot、赎回和策略激活数据，或明确拒绝无法安全处理的状态。
- 单用户配置必须由数据库约束保证唯一，并发首次写入不得产生多行。
- 同基金 DCA 激活/新建必须串行化，唯一约束冲突不得泄漏为 500。

### R16 前端业务入口与查询性能

- EFFECTIVE 定投计划必须提供暂停/恢复入口，且与退役为 DRAFT 的语义分离。
- 基金列表与组合轮询不得逐基金加载全部历史交易实体求和，应使用批量聚合查询。

### R17 总资金池与单基金硬上限

- 外部入金只有一种语义：正数金额累加到单用户总资金池，不直接归属某只基金。
- 每只基金保存可编辑的仓位上限比例，默认 30%，只能在 `(0, 30%]` 内调整。
- 所有买入类交易在最终确认前必须锁定基金并校验：`当前持仓市值 + 本次投入 ≤ 总资金池 × 该基金上限`。
- 30% 是数据库和业务层共同保证的硬上限，不允许通过请求值、定投、转换或并发确认绕过。
- V20 不推测现有账户总资金池；现有持仓保留，但首次外部入金前禁止新增买入确认。

## Acceptance Criteria

- [x] AC1 分红场景下累计净值上涨但单位净值未盈利时，止盈不进入 ARMED。
- [x] AC2 单位净值达到启动线时进入 ARMED，`cyclePeakNav` 保存累计净值。
- [x] AC3 从真实 `DcaSuggestionJob.run()` 路径生成定投时存在独立事务，单只失败继续处理其他基金。
- [x] AC4 ADJUST_IN 后基金进入 HOLDING，ADJUST_OUT 至零后进入 CLEARED，超持仓调减被拒绝。
- [x] AC5 非交易日三批行情与信号生成均跳过，管理信号入口也不能绕过。
- [x] AC6 普通过期信号不能确认，周末周五信号仍可确认，绑定的 TRIGGERED 止盈信号可跨日确认。
- [x] AC7 用户可忽略信号，历史保留忽略状态，止盈生命周期正确恢复。
- [x] AC8 确认页卖出份额不超过持仓，接口错误有持久错误态，旧 BUILD/ADD 主流程文案消失。
- [x] AC9 后端全量测试在隔离 schema 中通过，不读取或污染开发业务数据。
- [x] AC10 前端 lint、test、build 通过，浏览器关键流程通过。
- [x] AC11 `PRODUCT.md`、`CONTEXT.md` 与 ADR-0015/0019 及当前页面一致。
- [x] AC12 所有业务 `/api/**` 对缺失/错误凭据返回 401，有效会话或正确 Key 可访问，静态资源与 Actuator 不受影响。
- [x] AC13 Flyway 默认严格拒绝未知 Missing，仅显式修复已知遗留 V7。
- [x] AC14 前端 CI 执行 lint、test、build 三道门禁。
- [x] AC15 部署前备份数据库，候选失败恢复数据库与上一 digest，提交后失败不覆盖新写入。
- [x] AC16 外部入金只累加总池，基金上限可在 `(0,30%]` 编辑，所有买入确认在锁内拒绝未配置总池或越界仓位。

## Constraints

- 不新增依赖。
- 不删除历史 SignalType/SignalReason 枚举值，保证存量数据可读取。
- 数据库 schema 变更、CI 配置变更必须取得用户明确授权。
- 不提交、不推送，除非用户另行明确要求。
