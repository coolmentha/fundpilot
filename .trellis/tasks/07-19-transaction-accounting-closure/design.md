# v0.7 技术设计

## 边界

- 后端继续以 `FundTransactionView` 作为交易展示契约，不把 Entity 暴露给前端。
- 确认规则继续由 `NavConfirmService`、`TransactionConfirmService` 和 `TransactionConfirmSupport` 负责；前端只展示后端结果，不复制净值、FIFO 或费用计算。
- 不改数据库 schema，不保存确认失败历史。

## 数据流

`PENDING 交易 → 交易发生日净值查询 → 当前状态/原因投影 → 操作确认页`

- 净值存在：买入类可返回预计份额所需的净值依据；最终确认仍由后端重新读取并计算。
- 净值不存在：返回“待净值确认”，不回退旧净值。
- 待确认账务只投影净值是否已入库；数据源失败没有持久化历史，不在此处推断。
- 转换交易：沿用 `relatedTransactionId`，展示联动关系；确认顺序仍由后端保证。

## 兼容与回滚

- 旧客户端可忽略新增可选字段。
- 只新增 View 字段或现有接口投影，不需要迁移。
- 回滚时移除投影字段和前端列即可，不影响账务数据。
