# 已有持仓改为按份额录入

## Goal

录入已有持仓时直接保存用户实际持有的份额，避免把“当前市值”展示成买入金额，并避免行情刷新后产生本金无故减少的误解。

## Background

- 当前 `FundCreateRequest.initialMarketValue` 表示已有持仓的当前市值。
- `FundService.openWithExistingPosition` 使用最近确认单位净值执行 `initialMarketValue / nav` 反推份额，并生成一笔 `INCREASE` 流水。
- 行情估值更新后，持仓市值会按反推份额重新计算，因此流水中的金额与页面当前市值立即不同。
- 用户已确认已有持仓应录入“持有份额”，而不是金额。

## Requirements

- 用 `initialHoldingShares` 替代 `initialMarketValue`，不保留两套已有持仓录入口径。
- `initialHoldingShares` 为空时创建观察基金，保持 `PENDING_HOLDING` 且不生成交易。
- `initialHoldingShares` 有值时必须大于 0；后端直接使用该值作为确认份额，不再用净值反推。
- 已有持仓仍需最近一期已确认单位净值，用于填充初始交易的 `nav` 和核算金额；缺少净值时创建失败并回滚。
- 初始交易金额按 `initialHoldingShares × 最近确认单位净值` 计算，表示建仓时点的核算市值，不作为用户投入成本。
- 成本单价继续由用户填写；未填写时默认最近确认单位净值。总盈亏继续按持有份额、当前净值和成本单价计算。
- 前端已有持仓表单显示“持有份额”“成本单价”“建仓日期”，移除“初始持仓市值”输入及其联动文案。
- 不修改数据库 schema、不新增依赖、不改变普通手动买入交易流程。

## Acceptance Criteria

- [x] 输入持有份额 `50.85` 后，确认交易和事实持仓份额均精确为 `50.85`，不受当前净值反推影响。
- [x] 最近确认单位净值为 `8.0647` 时，初始交易核算金额为 `50.85 × 8.0647`。
- [x] 输入成本单价 `6.96` 时，基金成本单价保持 `6.96`；未输入时默认最近确认单位净值。
- [x] 份额为空时不创建持仓；份额为 0 或负数时返回明确校验错误。
- [x] 缺少净值历史或行情拉取异常时，已有持仓创建事务完整回滚。
- [x] 前端请求仅发送 `initialHoldingShares`，不再发送 `initialMarketValue`。
- [ ] 后端定向测试、前端测试、lint 和构建通过。

## Out Of Scope

- 修复或迁移已经按旧金额口径创建的历史持仓。
- 修改普通买入、定投、转换和卖出交易的金额/份额语义。
- 新增“金额/份额”双模式切换。
