# 整理业务逻辑文档

## Goal

建立一套可导航、可维护、与当前实现一致的 FundPilot 业务逻辑文档，使开发者和 AI Agent 能快速理解产品边界、核心业务流程、状态变化、关键计算口径及权威决策来源。

## Background

- `docs/PRODUCT.md` 已提供产品能力总览，但没有完整描述业务流程、状态转换和失败语义。
- `CONTEXT.md` 同时承载领域术语、业务规则、数据源实现、缓存策略和历史开发顺序；用户要求本任务保留其原状，不在此次整理中重构。
- `docs/agents/domain.md` 仍只列早期 ADR，并包含已经过时的信号术语指引。
- `backend/基金纪律策略框架.md`、`backend/docs/` 和 `docs/prd-portfolio-pnl-manual-tx.md` 包含已退役的金字塔加仓、计划仓位、回测寻优或旧净值口径，缺少历史文档标识。
- 当前业务实现主要分布在基金与交易、定投、策略与信号、行情与估值、用户配置模块，并有对应测试覆盖。

## Requirements

- 详细业务文档主要面向开发者和 AI Agent，优先表达业务流程、状态变化、计算口径、异常语义及权威实现入口。
- `docs/PRODUCT.md` 保持面向产品理解的非技术总览，并作为详细业务文档入口之一。
- 保留 `CONTEXT.md` 的原有内容，本次新增业务文档通过 `AGENTS.md`、`docs/PRODUCT.md` 和 `docs/agents/domain.md` 建立入口。
- 在 `docs/business/` 建立业务逻辑索引，并按稳定业务能力拆分详细文档。
- 详细文档至少覆盖：基金与持仓生命周期、交易账本与净值确认、自动定投、卖出纪律与信号、行情估值与盈亏、资金池与仓位限制。
- 每个业务主题说明参与对象、前置条件、主流程、状态变化、关键规则、失败处理及相关代码、测试、ADR 入口。
- 明确文档权威性：代码和测试是当前可执行事实，已接受且未被后续 ADR 取代的 ADR 是决策依据，`CONTEXT.md` 是术语与核心契约，`docs/business/` 是当前流程说明，旧设计和旧 PRD 仅作历史参考。
- 明确兼容遗留：`SignalType.BUILD/ADD`、`StrategyParamStatus.CALIBRATED/CALIBRATION_FAILED` 等仍可读取，但不代表当前新业务流程。
- 业务术语、状态名、北京时间日期口径、单位/累计净值用途和交易类型必须与当前代码、测试及已接受 ADR 一致。
- 历史资料保留原位置和正文，只添加醒目的历史状态说明及当前文档入口，不删除或移动文件。
- 本次只调整文档，不修改业务代码、数据库、接口、依赖、外部领域模型或部署配置。

## Acceptance Criteria

- [x] 从 `AGENTS.md` 或 `docs/PRODUCT.md` 能在两次链接内到达任一核心业务主题。
- [x] `docs/business/README.md` 能说明文档层级、权威性、核心主题和历史资料位置。
- [x] 每个核心业务主题均包含主流程、状态/结果、关键约束、失败语义和实现证据。
- [x] 文档清楚区分当前能力、兼容遗留和历史决策。
- [x] 相同概念在不同当前文档中使用一致术语，且不存在互相冲突的当前规则。
- [x] 所有内部 Markdown 链接均可解析，引用的代码、测试和 ADR 文件真实存在。
- [x] 当前业务文档不把金字塔加仓、BUILD/ADD 新信号、计划总仓位、回测寻优或累计净值记账写成现行能力。
- [x] `git diff` 仅包含本任务的文档与 Trellis 任务文件，不包含无关格式化或用户已有改动。
- [x] 通过内部链接检查、关键术语扫描和 `git diff --check`；验证结果写入任务记录或最终汇总。

## Out of Scope

- 修改或补建外部领域模型节点、关系和上下文。
- 重构或精简 `CONTEXT.md`。
- 修改业务实现以迁就现有文档，或顺手修复源码注释。
- 删除、移动或重写 ADR、旧 PRD、旧架构设计和原始策略框架。
- 统一翻译所有既有英文 ADR 标题或大规模格式化文档。
- 新增 Markdown 工具依赖、CI 检查或文档站点生成器。
