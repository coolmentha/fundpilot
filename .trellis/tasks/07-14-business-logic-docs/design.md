# 业务逻辑文档整理设计

## 文档权威性

按以下顺序处理冲突：

1. 当前代码与测试：可执行事实。
2. 未被后续决策取代的 ADR：决策原因与约束。
3. `CONTEXT.md`：领域术语和跨模块核心契约。
4. `docs/business/`：当前业务流程、状态机和失败语义。
5. `docs/PRODUCT.md`：面向产品理解的能力总览。
6. 旧 PRD、旧架构设计和原始策略框架：历史背景，不作为当前契约。

若代码与 ADR 存在未解释冲突，本任务记录当前代码行为并链接 ADR，不擅自修改业务实现。

不移动现有历史文件，避免破坏外部链接和提交历史。

## 内容模板

每份详细业务文档按实际需要使用以下结构：

- 业务目标与边界
- 核心对象和状态
- 主流程或时序图
- 状态转换
- 关键规则与计算口径
- 失败与降级
- 兼容遗留
- 实现与验证入口
- 相关 ADR

流程包含三个以上阶段时使用 Mermaid 流程图或状态图；简单规则使用表格或短列表，避免装饰性图示。

## 关键整理决策

### 当前与遗留分开

- 当前信号引擎只产生 `NONE/SELL`；`BUILD/ADD` 仅用于历史日志兼容，回应服务仍可处理存量信号。
- 当前策略配置只使用 `PENDING_CALIBRATION <-> EFFECTIVE`；`CALIBRATED/CALIBRATION_FAILED` 仅为存量枚举兼容。
- `FundStatus` 在交易确认或调整交易落账后，根据全部 `CONFIRMED` 交易的净份额重算；生成信号或创建普通 `PENDING` 交易不会直接清仓或建仓。
- 常说的“7 天保护”在系统内按 5 个交易日执行；定投止盈逐 lot 保护，逻辑止损可突破，手动卖出不经过建议信号门控。

### 记账与分析口径分开

- 单位净值用于份额、金额、市值、成本、申购赎回和仓位上限。
- 累计净值用于复权涨跌、年线、MACD、高点和回撤。
- 盘中估值只进入内存缓存，不写 `fund_nav_history`；估值失败必须失效旧估值并向前端表达未知。

### 自动执行与建议分开

- 定投计划是已授权的自动执行，直接生成 `INVEST/PENDING` 交易，不进入信号引擎。
- 卖出纪律只生成建议；用户确认后才创建 `DECREASE/PENDING` 交易，净值确认后才改变事实持仓。

## 风险与控制

- 风险：将源码注释中的旧描述误当成当前行为。控制：以方法实现和测试断言为准，不只读类注释。
- 风险：复制业务规则造成未来多处漂移。控制：总览只摘要并链接，详细规则只在一个主题文档中完整说明。
- 风险：历史资料被搜索命中后误用。控制：统一加历史提示，并在 Agent 指引中明确权威顺序。
- 风险：链接路径在 Windows/Markdown 环境下失效。控制：全部使用仓库相对路径，并执行链接存在性检查。

## 回滚

本任务仅修改 Markdown 和 Trellis 任务文件。回滚时可按文件恢复，不涉及数据迁移、运行时状态或依赖变更。
