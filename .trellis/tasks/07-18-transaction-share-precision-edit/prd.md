# 份额精度与未确认流水编辑

## Goal

让用户能够可靠地全量卖出或转换持仓，并在确认前修正交易流水，不再要求用户手工输入界面未展示的高精度份额。

## Background

- 系统按 `(金额 - 申购费) / 单位净值` 计算份额，事实持仓可能包含 8 位小数。
- 当前持仓仅显示 2 位、卖出输入也限制 2 位；例如事实持仓 `605.36974183` 被输入为 `605.37` 后，后端会正确判定为超卖。
- 后端必须继续基于锁定后的 CONFIRMED 事实持仓严格防止超卖，不能用全局模糊容差掩盖差额。
- `ADJUST_IN/ADJUST_OUT` 创建时立即 CONFIRMED，不属于“未确认流水”。普通买卖、信号、定投和转换可以处于 PENDING。

## Requirements

- R1：基金份额的全栈最小单位统一为 0.01 份，所有写入使用 `HALF_UP` 保留 2 位。
- R2：交易、lot、赎回明细和持仓聚合均只保留 2 位份额；存量数据通过一次性事务重放迁移，不保留隐藏高精度尾差。
- R3：卖出和转出提供“全部”操作，直接冻结当前两位事实持仓；用户侧份额始终按 2 位展示和输入。
- R4：仅 PENDING 流水允许修改；CONFIRMED/CANCELLED 继续保持不可变。
- R5：所有来源的 PENDING 流水均可修改，不限于手工录入；买入类修改金额和交易日期，卖出类修改份额和交易日期。
- R6：来源、所属基金、信号关联、定投关联及转换目标不可修改；转换转入腿是派生记录，不提供独立编辑入口，转出腿修改交易日期时同步转入腿。
- R7：流水修改必须复用创建时的字段校验，并保持转换双腿、信号关联和定投关联一致。
- R8：修改与确认并发时只能有一个状态转换成功，不得产生超卖或半条转换流水。
- R9：冻结后的全量份额在确认时仍按届时锁定的事实持仓严格校验；期间新增的持仓不自动加入，期间减少持仓导致不足时正常拒绝。
- R12：部署前必须完成数据库备份；迁移或账本重放失败时阻止应用启动，不允许带半完成账本运行。
- R10：基金详情交易流水和全局操作确认工作台都提供 PENDING 编辑入口，并遵循同一字段与状态规则。
- R11：修改信号或定投生成的 PENDING 流水只影响本次执行记录；保留原关联，不反向修改信号、策略或定投计划。

## Acceptance Criteria

- [ ] 存量事实持仓 `605.36974183` 迁移为 `605.37`，选择“全部卖出/全部转出”可确认并清仓为 0。
- [ ] 新买入、初始持仓、调整、信号卖出及转换产生的份额均为 2 位小数。
- [ ] 部分卖出超过锁定后的事实持仓仍返回 `INSUFFICIENT_HOLDING_SHARES`。
- [ ] PENDING 流水可修改其业务输入字段，修改后列表立即展示新值。
- [ ] CONFIRMED/CANCELLED 流水修改被拒绝，且原记录不变。
- [ ] 转换流水修改后两腿仍保持同一交易日和关联关系，确认时不出现半状态。
- [ ] 修改信号/定投生成的流水后，关联记录和后续计划参数保持不变。
- [ ] 后端服务测试覆盖全量卖出、部分超卖、状态竞争和转换一致性；前端测试覆盖“全部”与编辑入口。
