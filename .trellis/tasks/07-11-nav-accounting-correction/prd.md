# 修复基金账目净值口径并重算历史数据

## Goal

修复真实交易账目误用累计净值、申购费未进入成本、lot 使用确认时间等问题，并对存量数据执行一次可回滚、可重复判定的账本重建，使份额、金额、手续费、成本价、FIFO lot 与止盈计算恢复一致。

## Background

- `fund_nav_history.nav` 是单位净值，用于真实申购、赎回、份额和持仓市值。
- `fund_nav_history.accumulated_nav` 是累计净值，仅用于前高、年线、MACD、回撤和收益率等复权分析。
- 当前两个交易确认入口使用累计净值；买入成本使用扣费后金额；lot 和赎回持有期使用确认时间。
- 用户已确认修改口径并重算历史数据，允许创建 `hotfix/nav-accounting-correction` 和执行数据库数据修复。

## Requirements

- R1：自动确认和手动确认必须按交易发生日读取单位净值，并将单位净值写入 `fund_transaction.nav`。
- R2：买入到账份额仍按 `(amount - purchaseFee) / unitNav` 计算，但成本价分子必须使用用户实际投入的 `amount`，申购费计入成本。
- R3：买入 lot 的 `acquireDate`、卖出赎回费持有期终点和成熟份额判断必须使用 `tradeDate`；仅存量空值才回退 `createdDate/confirmTime`。
- R4：持仓市值和总盈亏使用单位净值；今日涨跌、前高、技术指标和止盈回撤继续使用累计净值涨跌口径。
- R5：历史重算保留交易、信号和审计记录，重算 CONFIRMED 交易的单位净值、派生金额/份额/手续费，重建 FIFO lot、赎回明细和基金成本价。
- R6：历史初始持仓若存在用户成本价，重建时从原始 onboarding lot 保留该成本，不得静默改成单位净值。
- R7：受旧成本和收益口径影响的定投止盈运行周期重置为 `ACCUMULATING`，清理周期高点、触发信号和冷静期字段；参数版本和用户自定义值保持不变。
- R8：历史重算必须有一次性状态记录；成功后不重复执行，失败时整次回滚并在下次启动重试。
- R9：同一定投计划同一北京时间自然日只能有一笔未软删交易，由数据库唯一索引兜底；迁移先消解存量重复并由账本重建修正派生结果。
- R10：历史已执行的买卖决策和 SignalLog 不回写、不删除，仅修复账目派生数据。

## Acceptance Criteria

- [ ] 单位净值与累计净值不同时，买入份额、卖出金额、市值和总盈亏均使用单位净值。
- [ ] 1000 元买入扣除申购费后，成本价仍等于 1000 / 到账份额。
- [ ] 一年前发生、今天确认的交易按一年前的 lot 日期和赎回持有期处理。
- [ ] 两个确认入口对单位净值、费用、lot 和成本产生相同结果。
- [ ] 历史重算后 `sum(CONFIRMED buy shares) - sum(CONFIRMED sell shares)` 与事实持仓一致。
- [ ] 历史重算后每个 lot 的 `acquireTxId`、剩余份额和赎回明细可追溯。
- [ ] 历史重算失败不留下半完成账本；成功后重启不再次执行。
- [ ] 并发生成同计划同日定投时数据库只接受一笔。
- [ ] 完整后端测试、Flyway 空库/升级库验证和前端构建通过。

## Out of Scope

- 认证授权、CI/CD、数据库备份机制。
- 信号拒绝/忽略、定投暂停 UI、跟踪指数编辑等其他审查项。
- 重写历史 SignalLog 或推测用户当时本应做出的交易决策。
