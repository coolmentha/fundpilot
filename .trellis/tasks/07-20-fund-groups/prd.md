# 基金分组

## Goal

支持用户按自定义分组整理基金，降低基金较多时在“基金管理”和首页“我的持仓”中的查找成本。

## Confirmed Facts

- `FundEntity` 当前仅有系统定义的 `fundCategory`，没有用户分组字段。
- `/api/funds` 返回的 `FundView` 同时供 `FundsPage` 和 `FundWatchlist` 使用。
- 分组属于基金档案信息，不参与持仓、收益、交易或信号计算。
- 当前项目为单用户部署，不需要处理分组的用户归属。

## Requirements

- 用户可以为基金指定任意多个分组，也可以不分组。
- 新建和编辑基金时均支持选择已有分组，也支持输入新名称即时创建。
- 提供轻量“管理分组”弹窗，支持重命名、删除和排序，不新增独立页面。
- 基金管理页和首页持仓页使用单选分组筛选，一次只查看一个分组。
- 筛选项包含“全部”和各自定义分组，不提供“未分组”筛选项。
- 基金允许不加入任何分组；此类基金仅在“全部”中展示。
- 删除分组仅删除分组及基金关联，保留基金档案、持仓、交易、信号和收益数据。
- 删除确认提示该分组关联的基金数量。
- 管理分组弹窗使用拖拽调整分组顺序，并兼容桌面鼠标与移动端触控。
- 拖拽排序先保存在弹窗草稿中，点击“保存”后统一提交；取消或关闭不保存。
- 分组名称保存前去除首尾空格，长度为 1–20 个字符，按大小写不敏感规则保持唯一。
- 分组名称允许中文、英文、数字和常见符号。
- “管理分组”入口仅放在基金管理页；首页“我的持仓”只提供分组筛选。
- 两个页面默认选择“全部”，筛选状态不改变后端数据。
- 两个页面使用 Ant Design 标签页筛选；“全部”固定在最前，自定义分组按保存的排序展示，溢出由组件收纳。
- 基金管理页和首页“我的持仓”展示基金分组。
- 分组不得改变现有持仓、收益、交易、信号与归档语义。

## Acceptance Criteria

- [ ] 用户可以设置、修改和清除基金分组。
- [ ] 用户可以在编辑基金时即时创建分组。
- [ ] 用户可以在管理弹窗中重命名、删除和调整分组顺序。
- [ ] 未分组基金仍可正常展示和操作。
- [ ] 基金管理页与首页持仓页按最终确认的交互展示分组。
- [ ] 两个页面一次最多选中一个分组；选择“全部”时展示所有符合页面原有条件的基金。
- [ ] 现有基金迁移后保持有效，默认处于未分组状态。
- [ ] 新建和编辑基金时可以保存空分组选择。
- [ ] 删除分组后，原关联基金仍可在“全部”中正常查看和操作。
- [ ] 删除确认文案包含将被移出分组的基金数量。
- [ ] 用户可以通过鼠标或触控拖拽调整分组顺序，刷新后顺序保持。
- [ ] 未保存排序在取消或关闭管理弹窗后不生效。
- [ ] 空名称、超长名称和大小写不同的重复名称均被拒绝并显示明确提示。
- [ ] 首页持仓区不提供创建、重命名、排序或删除分组的操作。
- [ ] 分组标签页顺序与管理弹窗保存的顺序一致，分组较多时仍可访问全部分组。
- [ ] 后端测试、前端 lint/test/build 全部通过。

## Out of Scope

- 分组级交易、收益核算或策略规则。
- 多用户分组隔离。
- 分组颜色、图标和分组级统计。
