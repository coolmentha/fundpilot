# 修复交易确认与账本一致性问题

## Goal

修复交易自动确认、基金转换、手工调整交易和交易日历同步中的一致性缺陷，确保交易状态、事实持仓、FIFO lot 和净值日期口径不会互相冲突。

## Requirements

### R1 夜间确认使用正确交易日

- 次日 03:00 的 `NavConfirmJob` 必须使用前一日 UTC 00:00 作为净值查询日期。
- 时间计算必须可测试，不直接依赖不可替换的系统当前时间。

### R2 基金转换状态必须保持一致

- 两条腿均为 PENDING 时，只有两只基金同一交易日净值都可用才批量确认，按“转出 -> 金额回填 -> 转入”顺序在同一事务完成。
- 对历史遗留的“转出 CONFIRMED、转入 PENDING”状态，只确认转入腿，不得重复确认转出腿。
- 任一腿已 CONFIRMED 时，不允许通过撤销另一条 PENDING 腿制造半撤销状态。

### R3 ADJUST 与 lot 口径一致

- ADJUST_IN 不建收费 lot；后续卖出时，事实持仓中超出 open lot 的份额允许按零赎回费降级处理。
- ADJUST_OUT 录入时同步减少 open lot，避免 lot 余额高于事实持仓；该调整不产生赎回记录和手续费。
- 普通超出事实/lot 可用范围的卖出仍保留 `INSUFFICIENT_LOTS` 保护。

### R4 手工交易输入有效

- 所有买入类 `amount` 和卖出类 `shares` 必须为正数。
- 前后端都提供正数约束；后端为最终校验边界。

### R5 日历同步并发幂等

- 新增交易日必须使用数据库原子 upsert/insert-if-absent，定时任务、启动预热、手动接口或多实例并发时不得因唯一索引冲突回滚整批同步。

### R6 文档与实现同步

- `CONTEXT.md` 更新为七类交易来源，并记录 ADJUST 的账本语义。
- 交易日历更新为新浪源自动同步，不再保留“人工维护”的旧描述。

## Acceptance Criteria

- [ ] AC1 固定时钟在某日 03:00 执行 Job，传给确认服务的是前一日 UTC 00:00。
- [ ] AC2 转出已确认、转入待确认时，从转入腿发起确认不会再次消费转出基金 lot。
- [ ] AC3 转换任一腿已确认时，撤销另一腿返回业务错误且两条状态不变。
- [ ] AC4 两腿均待确认但任一基金缺少当日净值时，两腿都保持 PENDING。
- [ ] AC5 ADJUST_IN 后卖出“已有 lot + 调增份额”不会因部分 lot 不足失败，未跟踪部分按零费率处理。
- [ ] AC6 ADJUST_OUT 会同步减少 open lot，且不生成赎回明细。
- [ ] AC7 普通手工交易的零数、负数金额或份额被前后端拒绝。
- [ ] AC8 交易日重复或并发写入返回 0/1 插入结果，不抛唯一索引异常。
- [ ] AC9 后端完整测试、前端构建通过；推送后 GitHub CI 全部通过才算完成。

## Constraints

- 不新增依赖。
- 不修改数据库 schema。
- 不删除或弱化现有有效测试。
- 不触碰用户未跟踪的 `frontend/inspect*.cjs` 文件。
