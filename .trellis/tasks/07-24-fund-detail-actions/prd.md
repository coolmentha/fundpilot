# 补全基金详情操作入口

## Goal

让用户在单只基金详情中看到待执行事项、交易费率，并可直接进入既有的处置或档案编辑流程，减少在全局页面和基金管理页之间的往返。

## 已确认事实

- 基金详情已有交易、策略、信号、行情、定投五个 Tab。
- 待确认交易由既有 `usePendingTransactions` 获取，信号处置在 `/signals?fundId=:id` 完成。
- `useFundFeeRates` 已返回申购折扣与赎回费率阶梯；基金编辑仍在 `/funds` 页面完成。
- 本任务不增加后端字段、不改变交易或信号状态机，也不引入外部成交对账。

## Requirements

1. 详情顶部展示当前基金的待处理摘要：待确认交易数量、待回应信号数量；存在事项时提供对应的处置入口。
2. 详情页展示申购参考费率和完整赎回费率阶梯；无可用费率时显示明确的缺失状态。
3. 详情页提供返回基金管理并编辑当前基金的入口；目标页面自动打开该基金的既有编辑弹窗。
4. 保持现有路由、全局信号处置和交易确认行为不变；所有数据显示遵循既有加载与空值约定。

## Acceptance Criteria

- [ ] 有该基金 PENDING 交易时，详情页显示数量并可前往 `/confirm?fundId=:id`；无待确认交易时不显示误导性操作。
- [ ] 有该基金待回应信号时，详情页显示数量并可前往 `/signals?fundId=:id`；已回应、已忽略或过期信号不计入待办。
- [ ] 申购折扣和赎回费率阶梯可在详情页阅读；缺失时显示 `未爬取` 或等价明确状态。
- [ ] 从详情页点击编辑基金后，基金管理页自动打开对应基金编辑弹窗，且不影响直接访问 `/funds` 的既有行为。
- [ ] 前端 lint、测试与生产构建通过。

## Out of Scope

- 外部基金平台成交回执或自动对账。
- 基金推荐、评级、基金经理和持仓研究数据。
- 新增、修改或删除后端 API 与数据库结构。
