# FundPilot v0.14.0 版本计划：提醒条件引擎与纪律收敛

> 基线版本：v0.13.0（2026-09-25）
> 目标版本：v0.14.0
> 版本主题：把「卖出纪律」的建议能力迁移到邮件提醒，删除 Discipline 模块；提醒规则由「固定三阈值」升级为用户可配的指标条件引擎
> 推进顺序：A（条件引擎）→ B（建议型提醒迁移）→ C（删除纪律模块 + 分类搬迁）
> 状态：**已发布**

## 0. 版本定位与决策记录

v0.14.0 是一次**模块级收敛 + 能力升级**：Alerting 从「只会盯涨跌幅」升级为「可配的技术指标条件引擎」，同时接管 Discipline 里真正有价值的那部分（逻辑破坏止损与回撤止盈的判定 + 建议卖出份额），然后删除 Discipline 模块。

### 0.1 已拍板决策（本版本执行的依据）

| 编号 | 决策 | 说明 |
| --- | --- | --- |
| D1 | 迁移与删除**同版本完成**，验证方式改为**离线比对** | 不采用「新旧并行观察一个完整周期」；用历史净值/指标数据逐条回放新逻辑 vs 旧 `AdvicePolicy`，结论一致即通过 |

## 1. 现状盘点：现在的参数维度有哪些

### 1.1 提醒规则（Alerting）——只有 1 个数值维度

表 `alert_rule`（`V55__add_alert_rule_and_notification.sql`）：

| 字段 | 取值 | 是否用户可配 |
| --- | --- | --- |
| `scope` | `GLOBAL` / `FUND` | 可配（2 选 1） |
| `rule_type` | `RISE` / `DROP` / `PROFIT` | 可配（3 选 1） |
| `threshold` | 约束 `0 < threshold ≤ 1` | 可配（1 个数） |
| `enabled` | 布尔 | 可配 |

口径固化在 [AlertRule.java](file:///d:/self-project/fundpilot/backend/src/main/java/com/fundpilot/backend/alerting/domain/alertrule/AlertRule.java#L66-L75)：`RISE/PROFIT` 用 `observedValue ≥ threshold`，`DROP` 用 `observedValue ≤ -threshold`；观测值来自 [AlertFundFactsGateway.java](file:///d:/self-project/fundpilot/backend/src/main/java/com/fundpilot/backend/alerting/application/gateway/ruleevaluation/AlertFundFactsGateway.java#L24-L29)——`RISE/DROP` 取当日涨跌幅、`PROFIT` 取持仓收益率。

**结论：现在的提醒只能表达「涨了多少 / 跌了多少 / 赚了多少」三件事，其余一切技术指标都无法配置。**

### 1.2 行情指标快照（MarketData）——10 个字段，口径**全部硬编码**

表 `market_indicator_snapshot`（读取见 [MarketIndicatorRepositoryImpl.java](file:///d:/self-project/fundpilot/backend/src/main/java/com/fundpilot/backend/marketdata/infrastructure/persistence/indicator/MarketIndicatorRepositoryImpl.java#L23-L29)）：

| 字段 | 实际口径 | 窗口是否可配 |
| --- | --- | --- |
| `current_nav` | 最新累计净值 | — |
| `price_above_year_line` | 净值 > 近 **250** 日累计净值均线 | 否（写死 `YEAR_LINE_WINDOW=250`） |
| `year_line_rising` | 今日 MA250 > 昨日 MA250 | 否 |
| `weekly_macd_state` | 周线 MACD 柱相对于上一周的 4 态枚举 | 否（EMA **12/26/9** 写死在 `weeklyMacd`） |
| `volume_state` | 基准指数日 K 量 vs 近 **20** 日均量 | 否（写死 `VOLUME_WINDOW=20`，阈值 1.5× / 0.5× 也写死） |
| `weekly_drop_percent` | 近 **5** 个交易日首尾跌幅 | 否（写死 `WEEKLY_DROP_WINDOW=5`） |
| `is_sixty_day_high` | 净值 ≥ 近 **60** 日最高 | 否（写死 `SIXTY_DAY_WINDOW=60`） |

全部常量集中在 [MarketIndicatorRefreshCommandHandler.java](file:///d:/self-project/fundpilot/backend/src/main/java/com/fundpilot/backend/marketdata/application/command/indicatorrefresh/MarketIndicatorRefreshCommandHandler.java#L46-L54)，计算细节在同类 [#L263-L343](file:///d:/self-project/fundpilot/backend/src/main/java/com/fundpilot/backend/marketdata/application/command/indicatorrefresh/MarketIndicatorRefreshCommandHandler.java#L263-L343)。

两个容易误解的口径，先记下来免得后面踩坑：

- `weekly_drop_percent` 是**近 5 个交易日**的首尾跌幅，**不是自然周**（名字有误导性）。
- `weekly_macd_state` 只输出「柱在放大/缩小」的 4 态，**不含金叉/死叉**，也不暴露 DIF/DEA 数值。
- 周线序列按「周日为一周结束」聚合，且**要求至少 30 周**才输出，否则该字段为 `null`。

### 1.3 已有 vs 缺口（对应你说的 MACD / 年线 / M20 M50 M5）

| 你说的维度 | 现在有没有 | 具体到什么程度 |
| --- | --- | --- |
| 年线 | **有** | 只有 250 日窗口；只给「价在上/下」「均线上升/下降」两个布尔，窗口不可调 |
| MACD | **有周线** | 只有 4 态枚举，快/慢/信号线不可调，无金叉死叉 |
| M20 / M50 / M5 / M60 | **全都没有** | 均线体系除 MA250 外一律不存在；也没有「价格与均线关系」「均线与均线关系」这类通用能力 |
| 日线 MACD | **没有** | 只有周线 |
| 金叉 / 死叉 | **没有** | 4 态枚举里没有交叉事件 |
| 上穿 / 下穿 | **没有** | 年线只给「当前在上/下」的静态布尔，不给「今日由下穿上」的事件 |
| 量能 | **有** | 只有 3 态枚举（`HIGH_DROP`/`NORMAL`/`LOW_STABLE`），窗口与倍数阈值都不可调，且绑定在基准指数上 |
| RSI / KDJ / 布林带 | **没有** | 不存在 |
| PE 估值 | **数据有，未接入 → 本版本接入**（D8） | `index_valuation` 已落库（`IndexValuationRepository`、`indexvaluation` 包），但没有任何规则读它 |

**这就是本版本 A 段要解决的核心矛盾**：现在这些指标是「服务端预先算好、固定口径、存成枚举」的形态，无法支撑「用户自己填窗口」。靠给快照表加列会组合爆炸（MA 窗口 × MACD 三参数 × 量能窗口……），所以必须换成**按需计算**。

`discipline_strategy` 的 6 个参数（校验见 [DisciplineStrategy.java](file:///d:/self-project/fundpilot/backend/src/main/java/com/fundpilot/backend/discipline/domain/strategy/DisciplineStrategy.java#L176-L186)）：

| --- | --- | --- |
| `activation` | 止盈启动收益率 | 宽基 15% / 行业 20% / 主动 15% / 混合 12% |
| `pullback` | 高点回撤比例 | 6% / 8% / 7% / 5% |
| `harvest` | 浮盈收割比例 | 50% / 50% / 50% / 40% |
| `minimumHolding` | 最低保留仓位 | 50% / 40% / 50% / 60% |
| `maxSingleSell` | 单次最大卖出比例 | 统一 20% |
| `cooldownDays` | 冷静期交易日 | 统一 10 |

### 1.5 生产实测：纪律从未产出过有效建议

| 测项 | 实测结果 |
| --- | --- |
| `discipline_advice` | 仅 8 行，理由全是 `NO_STRATEGY`(5) / `INSUFFICIENT_MARKET_DATA`(3)，**无一条 SELL**，最新停在 2026-07-10 |

## 2. 可配性设计

### 2.1 三层能力

| 层 | 能力 | 本版本 |
| --- | --- | --- |
| 层 1 | 基础形态：涨跌幅 / 收益率 与阈值比较 | 保留，映射进新模型 |
| 层 2 | **指标本体可调**：MA 窗口、MACD 快/慢/信号线、量能窗口与倍数 | 新增 |
| 层 3 | **事件型**：金叉/死叉、上穿/下穿 | 新增 |

### 2.2 存储形式：结构化条件数组（**不用表达式语言**）

一条提醒规则 = 一组条件的**合取（AND）**。每条条件三要素：**指标 → 关系 → 参数**。

```json
{
  "scope": "FUND",
  "portfolioFundId": 12,
  "match": "ALL",
  "conditions": [
    {"indicator": "PRICE_VS_MA",   "params": {"window": 250},                        "relation": "BELOW"},
    {"indicator": "MACD_HISTOGRAM","params": {"timeframe": "WEEKLY", "fast": 12, "slow": 26, "signal": 9}, "relation": "GREEN_EXPANDING"},
    {"indicator": "MA_CROSS",      "params": {"fast": 20, "slow": 50},               "relation": "DEATH_CROSS"},
    {"indicator": "VOLUME_RATIO",  "params": {"window": 20, "multiple": 1.5},        "relation": "ABOVE"},
    {"indicator": "HOLDING_RETURN","params": {},                                     "relation": "ABOVE", "value": 0.15}
  ]
}
```

落库为 `alert_rule.conditions JSONB`（新列），`threshold` 列保留给「单条件 + 阈值」的存量兼容路径。

**为什么不做表达式语言**：D3 已明确排除。结构化数组能被前端表单 1:1 生成、能被服务端按枚举校验、能被离线比对脚本直接回放；表达式语言反之，且会引入解析器、沙箱、注入面三个新风险。

### 2.3 「方便用户配置」的落点（前端条件构建器）

这是 D3 里「方便用户配置」的具体兑现方式，逐条对应：

1. **条件行 = 三个下拉/输入**：指标（带中文名 + 一句白话解释）→ 关系（选项随指标联动）→ 参数（只显示该指标需要的参数，带默认值）。
2. **默认值兜底**：每类指标预置默认参数（如 MA 默认 250、MACD 默认 12/26/9、量能默认 20 日与 1.5 倍），用户不改也能直接存。
3. **参数带取值范围与说明**：如「均线窗口：5–250 个交易日」「量能倍数：1.0–3.0」。
4. **组合逻辑先只做「全部满足」(AND)**：不做嵌套、不做 OR。够用且不引入复杂度。
5. **预设模板一键套用**：给出「逻辑破坏止损」「回撤止盈」两个现成模板，对应迁移过来的旧纪律语义，用户点一下就能得到等价规则。
6. **实时预览**：保存前用最近一个交易日的数据试算一遍，直接告诉用户「当前不满足 / 满足，命中的是第 2 条条件」——避免建完规则却长期不触发、不知道哪里配错了。

### 2.4 求值边界（重要）

- **通用求值器**只处理**无状态**条件（层 1/2/3 全部属于此类），纯函数，每天每规则算一次，无历史记忆。
- **建议型规则**（B 段迁移的 `LOGIC_BROKEN` / `TRAILING_STOP`）**不走通用求值器**，作为独立规则类型，自带状态机（周期峰值、ARMED/TRIGGERED/COOLDOWN）与建议份额计算。

两者**不混在一起**：混了会让通用求值器被迫持有状态，也会让「简单阈值规则」的语义被状态机污染。

## 3. 施工三段

### 3.1 A 段：提醒条件引擎

| 子任务 | 内容 | 验收 |
| --- | --- | --- |
| A-1 | **指标按需计算能力**：MarketData 新增「给定 (fundProductId, 指标种类, 窗口参数) → 现算取值」。数据源复用已落库的净值历史（`fund_nav_history`）、指数 K 线（`index_kline`）与指数估值（`index_valuation`），**不新增外部拉取** | 同一指标用不同窗口算出的值可复现；同一天内重复求值命中进程内当日缓存 |
| A-2 | **条件模型与求值器**：`alerting/domain/condition` 下新增条件值对象 + 求值器（纯函数，无 Spring） | 每个指标 × 关系组合有单测；参数越界被拒 |
| A-3 | **两日关系（事件型）**：`MA_CROSS` 需要「快线 vs 慢线」两日位置关系；`PRICE_CROSS_MA` 需要「价格 vs 均线」两日穿过——按需取两个交易日的指标值 | 金叉/死叉只在跨界当日触发，不重复触发 |
| A-4 | **首批五组维度**（D4 + D8）：① 周线 MACD 状态（含可调 12/26/9，含金叉/死叉）② 年线与区间位置（可调 MA 窗口 + 区间新高/新低）③ 量能状态（可调窗口与倍数）④ 持仓收益与回撤 ⑤ **PE 估值**（指数 PE 与其历史分位，走 `IndexValuationApi`） | 五组指标均可通过 `GET /api/alert-rules/indicators` 描述给前端 |
| A-5 | **元数据接口**：`GET /api/alert-rules/indicators` 返回全部指标的种类、中文名、说明、可选关系、参数定义（名称/类型/默认值/范围）——前端构建器由它驱动，**避免前后端各写一份枚举** | 前端新增指标只需改后端一处 |
| A-6 | **前端条件构建器**：`AlertRuleFormModal` 由三步向导改造为「范围 → 条件列表 → 预览确认」 | 满足 §2.3 的 6 条 |
| A-7 | **存量兼容**：生产现有 2 条规则（`RISE`/`DROP`/`PROFIT` + `threshold`）在迁移脚本中翻译为等价条件数组，`rule_type`/`threshold` 列语义保留 | 迁移后旧规则的触发行为逐条不变 |
| A-8 | **契约与通知改造**：`AlertRuleController.Request/View` 增加 `conditions`；`alert_notification.trigger_summary` 需能表达多条件命中 | 提醒记录页可读地展示「命中了哪些条件」 |

**A 段的关键决策（D5）**：指标**不落新快照列**，改为按需计算。理由：可配窗口的组合空间是无限的，落库必然组合爆炸；而净值历史与指数 K 线本就已全量落库，现算成本可接受（单基金单指标 O(窗口)），且当日缓存后每条规则只算一次。

## 5. 离线等价性验证方案（替代并行观察）

D1 要求「不并行观察一个周期」，因此用离线回放证明迁移无损：

| 步骤 | 做法 |
| --- | --- |
| 1. 取数 | 从生产库导出历史净值（`fund_nav_history`）、指数 K 线（`index_kline`）、以及 3 个 `EFFECTIVE` 策略的参数快照 |
| 2. 回放 | 对每个交易日、每个组合基金，分别运行**旧 `AdvicePolicy`** 与**新的建议型规则**，记录 `(action, reason, suggestedShares, 阶段)` |
| 3. 比对 | 逐条 diff；输出差异表（差异数应为 0） |
| 4. 归因 | 若有差异，逐条归因：属于「旧逻辑本就不该触发」（如 `NO_STRATEGY` 误报）还是「新逻辑漏判」；**只接受前者** |
| 5. 固化 | 差异表与脚本归档到 `docs/operations/`，作为删除纪律模块的前置证据（C-6） |

补充：生产 `discipline_advice` 只有 8 行且无一条 SELL，所以回放的主要价值是证明**不会因为迁移而凭空多出或漏掉 SELL**，而不是复现历史行为。

## 6. 通用验收与回归要求

- 每个子任务必须附带测试；新增测试应能在改动前失败、改动后通过。
- `SpringModulithStructureTest`、`DddLayerArchitectureTest`、`ModuleContractArchitectureTest` 必须持续通过；不得为通过测试而放宽断言。
- 涉及指标计算口径的改动，必须说明在**非交易日、长假跨周、上市不足窗口期（数据不足）** 三种情形下的行为。
- 通信能力（邮件）必须说明：**通知失败时业务是否仍完成**；**重复通知如何抑制**（沿用现有 `uq_alert_notification_rule_day_sent` 幂等键）。
- 前端新增指标时，指标枚举**只在后端维护一份**（A-5），前端不得硬编码第二份。
- 不可逆操作（C-5 的删表/删列）必须先备份，并在 `docs/operations/` 留下回滚说明。**删 `signal_log_id` 有顺序硬约束**：先改写 `AccountingRebuildService` 的来源判定并跑通账务重建回归，再删列（C-6）。

### 8.4 与原计划不一致的三处（如实记录）

1. **等价性回放（测试 A）唯一差异为 7 条不可达组合**：旧 `AdvicePolicy` 在「持仓状态 `OPEN` 且份额为 0」时返回「卖出 0 份」，新 `AlertSuggestionService.logicBroken` 增加了 `positive(holdingShares)` 前置校验故不卖。该单元格在会计口径下**不可达**（`OPEN` 必为正份额），**可达组合差异为 0**；7 条差异已逐条归因并接受（见归档报告 §3）。
2. **测试 C 生产回放两侧命中数均为 0**，与 §1.5 的生产实测一致；**回撤止盈缺少历史持仓快照**，故以 **8640 组参数/状态网格穷举**替代历史序列回放（生产 3 个 `EFFECTIVE` 策略 `take_profit_phase` 全为 `ACCUMULATING`，历史上无止盈触发事件需保真）。
3. **`TakeProfitParams` 的 `activation` 取值范围为 `(0, 1]`**：不复刻旧请求路径对 `activation < 1` 的额外收紧，新模型照搬领域校验、允许取 1（单测显式覆盖「允许取一」）。
