# FundPilot 产品文档

> 当前定位：场外公募基金的行情工作台与纪律执行平台。
> 单用户场景；系统负责计算、提醒、记账和审计，真实申赎仍由用户在基金平台完成。

## 一、产品边界

FundPilot 解决三个问题：

1. 集中查看指数、基金估值、净值走势、市场宽度、行业板块和主力资金流向。
2. 按计划自动生成定投交易，等待交易日净值确认后形成真实份额账本。
3. 对持仓执行定投止盈和逻辑破坏止损，生成 SELL 建议供用户确认或忽略。

当前系统不做：

- 不推荐买哪只基金。
- 不自动向基金公司下单。
- 不再生成 BUILD/ADD 买入信号。
- 不再维护金字塔档位、计划总仓位分配、回测或参数寻优。总资金池仅作为仓位风险预算分母，不恢复金字塔加仓。

历史 `BUILD/ADD` 枚举和值仅为读取存量 SignalLog 保留，不代表当前产品能力。

## 二、核心领域模型

### 2.1 基金与事实持仓

`FundEntity` 保存基金身份、分类、成本单价、单基金仓位上限和生命周期状态。仓位上限默认 30%，可向下调整但不能超过 30%。事实持仓不存冗余金额，始终由 CONFIRMED 交易份额聚合：

- `PENDING_HOLDING`：没有正持仓。
- `HOLDING`：CONFIRMED 净份额大于零。
- `CLEARED`：曾有交易但净份额已归零。

`fundCategory` 用于推荐定投止盈参数；`fundSubType` 用于决定行情和逻辑止损路径，两者不可合并。

### 2.2 交易账本

交易来源共七类：

- 买入方向：`INCREASE`、`TRANSFER_IN`、`INVEST`、`ADJUST_IN`。
- 卖出方向：`DECREASE`、`TRANSFER_OUT`、`ADJUST_OUT`。

普通买卖先写 `PENDING`，按业务 `tradeDate` 对应的单位净值确认后变为 `CONFIRMED`。`ADJUST_IN/OUT` 是账实修正，录入即确认，不计算净值和费用。

真实份额、持仓市值、成本和费用统一使用单位净值；累计净值仅用于复权涨跌、年线、MACD、峰值和回撤分析。

### 2.3 信号

当前信号引擎只生成：

- `NONE`：当日无需卖出。
- `SELL`：定投止盈或逻辑破坏止损。

信号操作状态动态投影为：无需操作、待回应、已回应、已忽略、已过期。普通信号只在最近交易日有效；当前止盈周期绑定的 `TRIGGERED` 信号可跨日等待处理。

## 三、行情工作台

首页 `/` 是行情工作台，包含：

- 组合今日收益、上涨/下跌基金数量和沪深京市场宽度。
- 用户关注指数实时行情。
- 自选基金盘中估值、今日涨跌、持仓和收益。
- 行业板块涨跌排行。
- 行业板块主力净流入/净流出排行。

实时接口读取后端内存缓存，前端轮询不得直接击穿外部行情源。指数 K 线优先读取本地 `index_kline` 缓存，缓存空时才允许实时降级获取。

北向资金接口属于遗留能力，不是当前行情工作台的验收项。

## 四、基金管理

### 4.1 新建基金

用户通过基金字典搜索并选择基金，系统自动回填名称、分类、子类型和跟踪指数。可选录入已有持仓：

- `initialMarketValue`：当前入仓市值。
- `costPerShare`：用户真实成本单价，不填时使用最近一期单位净值。
- `openedAt`：大致建仓时间，仅影响持有期分析起点。

初始持仓同步确认并创建 FIFO open lot；无净值历史或未配置总资金池时拒绝创建持仓，且不得绕过单基金仓位上限。

### 4.2 基金详情

基金详情包含行情/K 线、信号历史、定投止盈策略、定投计划以及交易流水和手工交易录入。

## 五、自动定投

定投计划支持日、周、月频率：

- 周计划只允许周一至周五。
- 月计划日为 1-28；遇休市顺延到下一个交易日，包括跨月顺延。
- `enabled=false` 暂停执行，但不删除计划。
- 同一基金同时最多一份 `EFFECTIVE` 计划。

14:55 的 `DcaSuggestionJob` 在交易日自动生成 `INVEST/PENDING` 交易。相同计划在同一北京时间自然日只能生成一次，CONFIRMED 或 CANCELLED 都视为本期已处理。

## 六、卖出纪律

### 6.1 定投止盈

定投止盈使用两套明确分离的净值口径：

- 单位净值：整体收益、浮盈金额和建议卖出份额。
- 累计净值：周期峰值和从峰值回撤。

状态机：

```text
ACCUMULATING -> ARMED -> TRIGGERED -> COOLDOWN -> ACCUMULATING/ARMED
```

整体收益达到 `profitActivationPercent` 后进入 ARMED；累计净值从周期高点回撤达到阈值时生成一次 SELL。建议份额同时受浮盈收割比例、单次上限、成熟可赎回份额和最低保留仓位约束。

用户确认后生成 `DECREASE/PENDING` 交易；忽略或撤销则恢复 ARMED，等待新的回撤。

### 6.2 逻辑破坏止损

- ETF/指数/指数增强：跌破年线、周 MACD 绿柱扩大、跟踪指数放量下跌同时成立。
- 主动/混合：跌破年线、周 MACD 绿柱扩大同时成立。

逻辑止损建议清空全部持仓，并可突破 5 个交易日保护窗口；系统仍只生成建议，不自动下单。

## 七、盈亏口径

- 今日涨跌：盘前 0、盘中 fundgz 估算、盘后累计净值实际涨跌。
- 今日盈亏：昨日持仓市值 × 今日涨跌幅。
- 总盈亏：持仓份额 ×（当前单位净值 - 成本单价）。
- 估值拉取失败时当前市值、今日盈亏和总盈亏应显示未知，不得用旧净值冒充当前值。

## 八、用户配置与管理

`/settings` 管理关注指数和总资金池。外部入金只能以正数累加到总池，不直接归属基金、不生成交易，也不因后续买入扣减。所有买入确认按“当前持仓市值 + 本次投入 ≤ 总资金池 × 单基金上限”校验。

`/admin` 提供行情刷新、信号生成、净值确认、基金字典和交易日历同步等管理操作。自动信号生成和自动定投必须同时受北京时间与交易日历约束。

`/monitor` 展示系统健康和任务运行状态。

## 九、数据与失败原则

- 外部行情源通过降级链访问；全部失败必须明确报错，不返回伪造零值。
- 估值是短时态缓存，不写入已确认净值历史。
- PENDING 交易缺少对应交易日单位净值时保持 PENDING，禁止使用未来或最新净值代替。
- 单只定时任务失败不得阻断其他基金。
- Controller 只做路由，业务规则放在 Service。
- 所有业务时间使用 `Instant`，北京时间自然日统一由 `ChinaTradingDate` 转换。

## 十一、权威决策

- ADR-0015：金字塔加仓退场，当前信号引擎只生成 SELL。
- ADR-0016：定投是自动执行，不是信号。
- ADR-0018：定投止盈参数模板和周期状态机。
- ADR-0019：单位净值用于账目，累计净值用于复权分析。

领域术语与边界以根目录 `CONTEXT.md` 为准；技术实现细节以 `.trellis/spec/`、ADR 和当前代码为准。
