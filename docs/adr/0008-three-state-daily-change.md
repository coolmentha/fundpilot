# 三态今日涨跌模型

「今日涨跌」是同一概念在三个数据阶段的投影：当日估值尚未出现时为 0 并使用最近确认净值；当日估值出现后使用 fundgz；当日净值落库后使用实际净值。A 股基金与 QDII 共用该状态机，差异只来自各自当日 `gztime` 出现的时间。

## Considered Options

- **A. 当日估值时间 + 净值落库判定（已采纳）**：当日净值已落库时使用实际涨跌；否则当缓存存在北京时间当日 `gztime` 时使用 fundgz 估值；`STALE/NOT_ATTEMPTED` 表示当日估值阶段尚未开始，今日涨跌为 0，持仓市值与总盈亏使用最近确认单位净值；空响应或失败保持未知。交易结束后净值尚未公布时继续使用最后一次当日估值。
- **B. 按市场配置固定交易时段**：为每只 QDII 维护美国、香港、欧洲等市场与夏令时。判定精确但需要 schema、API、UI 和人工维护，全球组合基金仍没有唯一时段。
- **C. 统一北京时间 09:30**：实现简单，但会把 QDII 在白天误判为交易中，并错过晚间生成的估值。
- **D. 两字段并存（dailyChangePct + estimatedChangePct）**：前端自行选择估算或实际值。会拆散同一业务概念并复制状态判断。

## Consequences

选 A 的理由：

1. 单一状态机：A 股基金和 QDII 的涨跌、今日盈亏与总盈亏继续由同一服务计算，不复制市场专用逻辑。
2. 数据驱动：`fundgz.gztime` 已包含每只基金的实际估值时间，不需要维护市场、时区和夏令时字段。
3. 净值优先：当日净值一旦落库立即覆盖估值，避免纯时间判断在净值公布时间不一致时选错数据源。
4. 交易前可用：当日估值尚未出现时，今日涨跌为 0，持仓市值与总盈亏使用最近一期已确认单位净值，不再显示空值。
5. 失败仍显式：`UNAVAILABLE/TIMEOUT/PARSE_ERROR` 不回退最近净值冒充交易中的当前值；旧估值也不会保留。

不选 B：当前模型不能可靠识别所有 QDII 的市场归属，新增维护面超过本问题需要。

不选 C：固定 A 股开盘时间不能表达 QDII 的晚间和跨自然日交易。

不选 D：两字段会把状态选择推给每个前端消费者。

## 刷新窗口

- A 股交易时段继续每 30 秒执行完整行情刷新。
- 周一至周五北京时间 09:00-23:59、周二至周六 00:00-05:59 增加估值专用刷新；A 股交易时段内跳过专用刷新以避免重复请求。
- 估值专用刷新不受中国交易日历阻断，避免中国节假日漏掉正常交易的境外市场。
- 扩展窗口只刷新基金估值，不刷新指数、市场宽度、板块或资金。

## 代价

- 扩展窗口增加 fundgz 请求量；继续使用共享限流和任务防重入。
- 当前会刷新全部支持普通净值的基金，因为项目没有可靠的基金市场归属。只有请求量实际成为瓶颈时再增加市场分类。
- 上游长时间返回旧 `gztime` 时会继续显示最近确认净值，这是以数据时间作为交易阶段信号的明确降级行为。
